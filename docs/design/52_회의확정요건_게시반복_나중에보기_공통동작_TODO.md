## 확정 사항
1. 게시 시간 기능을 추가한다.
2. 매일·요일별 반복 설정을 지원한다.
3. 나중에 보기는 다음 조회 주기에 조회한다. 기존 1시간 고정 연기 제안을 대체한다.
4. 닫기는 제출과 동일하게 취급한다.
5. 모든 팝업은 백그라운드 동작을 차단한다.
6. 선택지 개수 컨트롤 기능을 제공한다.
7. 개발 우선순위는 TEXT 템플릿 등록 → TEXT 게시 등록 → CS–SERVER API다. TABLE 생성·퍼블리싱·화면/API 개발 순서에 맞춰 인계한다.

## 책임과 적용 원칙
- 서버: 일정·대상·재노출·완료·중복 판정과 저장. Front/Server 담당자가 구현·통합 검증한다.
- WPF: 합의된 요청 전송, 단건 조회 응답 표시, 결과 저장 응답에 따른 다음 동작, UI 및 샘플 전달.
- 테이블 명칭을 WPF DTO에 직접 대응시키지 않는다. deliveryId·nextStatus 등의 최종 필드와 의미는 서버 제공 계약으로 매핑한다.
- 확정된 '닫기=제출'을 반영하되, 실제 요청 ENUM 통합이나 필수 문항·합격점·시청 조건 제거가 자동으로 확정된 것은 아니다. 유형별 버튼/결과 매핑을 작성하여 구현한다.
- 백그라운드 차단은 팝업 뒤 화면 조작 차단 요구로 반영한다. 다른 프로세스 실행 중지나 OS 전체 잠금까지 의미한다고 확대하지 않는다.
- 이번 변경은 TODO 문서 등록이다. 기존 코드·ALL/MINIMAL 명세를 이미 구현된 것처럼 바꾸지 않는다.

이번 확정 범위에 없는 3회 제한 ON/OFF, Agent 지연 조회의 구체 시간·조건, SecuerityNotify의 의미는 기존 별도 항목에서 관리한다. 확정된 나중에 보기 기능 자체를 이 항목 때문에 보류시키지 않는다. 응답률·대상자·로깅 없는 상시 팝업 제안을 매일/요일 반복 요건으로 부활시키지 않는다.

## 완료 기준
확정 요건이 WPF 동작·최종 API 샘플·문서에 일치한다. 결과 저장 응답으로 전송 완료/재시도/다음 조회를 구분한다. 모든 팝업 종료 및 표시 실패 시 백그라운드 차단이 해제된다. 정상·실패·반복·나중에 보기 및 유형별 결과 매핑을 WPF 범위에서 검증하고 미실행 항목을 남긴다.
