# 팝업 JSON 가공·요청 body 생성 정책 정리

작성: 2026-10-29 (KST)
상태: **정책 정리 완료(범위 확정) · 공통 함수 pickPopupFields로 통일(2026-10-30) · 테이블 구조 확인 대기**. 공통 모듈의 범용 재사용 원칙은 [독립 재사용·선택 필드 추출 TODO](20261030_PopupcommonComponent_독립재사용_필드추출_TODO.md)를 따른다(`toSaveRequest`는 proto 사용 사례 중 하나, `pickPopupFields`는 값 그대로·`topLevelKeys` 포함). 신규 숫자 TODO 번호는 임의 부여하지 않음.

## 1. 배경

- 프런트에서 어려운 작업: 관리자 편집값(팝업 JSON)을 가공해 게시정보·대상자·콘텐츠·문항 같은 **다른 테이블 API의 요청 body**를 만들거나, 화면마다 다른 데이터를 뽑는 일. 목적은 서식 유지·WPF 전달이 아니라 테이블별 요청 body 생성이다.
- 폐쇄망 DTIY3117은 팝업 본체를 JSON 한 컬럼(`POPU_BLTN_CN`)에 저장하고 계약 밖 관리용 필드는 그 JSON에서 제거한다(`SERVER_SAMPLE_FULL_JSON_API.md` §3). 게시 기간·활성 여부·대상자는 별도 컬럼·테이블로 간다.

## 2. 범위 결정

**최상위 필드는 입력란 값 수준이다. 어려운 부분은 `content`와 `questions` 두 곳뿐이다.** 정책과 공통 함수는 이 두 곳에만 둔다.

| 대상 | 처리 | 이유 |
|---|---|---|
| 최상위 필드(popupId·title·기간·크기·표시 스위치·hideDays 등) | `toSaveRequest` 결과에서 **key/value 그대로** 꺼낸다. 공통 함수 없음 | 평평한 값. 날짜 ISO·IMAGE 크기·완료 기준 정리는 `toSaveRequest`가 이미 한다 |
| `active`·`targetGroups` | `toSaveRequest` 결과의 최상위(`request.active`·`request.targetGroups`)에서 꺼낸다 | 편집값 `popup` 밖의 값 |
| `content`·`questions` | `pickPopupFields(toSaveRequestPopup(popup), { contentKeys, questionKeys })`로 필요한 키만 고른다 | content는 유형마다 키가 다르고 저장 정리 규칙이 있으며, 문항은 중첩 배열이다 |

## 3. 정책

### P1. 원천과 저장 경계 (2026-10-30 수정)

- **proto 등록 화면(RgstPop)**: 요청 데이터는 편집값 state가 아니라 `toSaveRequest(popup, active, targetGroups)` 결과에서 만든다. state에는 정리 전 값(`https://`가 없는 URL, 다른 유형의 content 키, 확인(CLOSE)일 때의 `footerAction`, 입력 형식 날짜)이 섞여 있다.
- **그 밖의 업무 화면**: `toSaveRequest`는 proto 사용 사례 중 하나일 뿐 기준 계약이 아니다. 화면이 입력한 값을 `pickPopupFields`로 **값 그대로** 고르고, 날짜 직렬화·키 이름·JSON 모양은 각 화면의 저장 경계에서 정한다([독립 재사용·선택 필드 추출 TODO](20261030_PopupcommonComponent_독립재사용_필드추출_TODO.md)).
- 최종 기본값·검증·정규화의 권위는 서버에 있다([WEB 표시 기본값 / SERVER 정책 책임 분리 TODO](20261030_PopupcommonComponent_WEB표시기본값_SERVER정책_책임분리_TODO.md)).

### P2. 최상위 필드 — key/value

- 구조 분해로 직접 쓴다. 최상위 필드 이름은 TypeScript가 검사한다.
- `{...popup}`은 얕은 복사다. `content`·`questions`·`targetGroups`는 state와 같은 객체이므로 만든 데이터를 고치지 않는다(고칠 때는 새 객체·`structuredClone`).
- 같은 데이터를 여러 화면에서 만들면 테이블별 함수 하나로 모은다(예: `toPostBody(request)`).

### P3. content·문항 — `pickPopupFields` 하나로

- `pickPopupFields(popup, { contentKeys?, questionKeys? })`: content에서 `contentKeys`의 키만, 각 문항에서 `questionKeys`의 키만 골라 새 객체(`{ content?, questions? }`)로 돌려준다. 옵션에 준 영역만 결과에 들어간다(빈 배열이면 빈 `{}`·빈 문항 객체). 없는 키·undefined 값은 빠지고 null은 남는다.
- 함수 자체는 저장 정리를 하지 않는다. 저장 기준 값이 필요하면 `toSaveRequestPopup(popup)` 결과를 넘긴다(다른 유형 키 제외·URL 보정·Footer 정규형).
- 타입: `questionKeys`는 `keyof PopupQuestion`, 결과 문항은 `Pick<PopupQuestion, 고른 키>`. 고르지 않은 필드 접근·없는 필드 이름은 컴파일 오류.
- content 키 목록은 `popupEditorTransform.ts`의 `COMMON_CONTENT_KEYS`·`CONTENT_KEYS_BY_TYPE` 하나만 쓴다. 새 content 옵션은 이 목록 → WPF DTO → 서버 검증·기본값 → MINIMAL·ALL 명세 → 가이드 공지 순서로 추가한다.
- 서식 본문은 짝으로 고른다(`textBlocks`↔`plainText`, `surveyTitleBlocks`↔`surveyTitle`, `descriptionBlocks`↔`description`).
- 문항: 새 문항·선택지 ID는 음수 임시 값(서버가 저장 시 채번). 선택지가 필요하면 `'options'`를 고른다. 유형별 필드는 QUIZ `isCorrect`·`questionScore`·`correctAnswer`·`answerMatchMode`, SURVEY 복수 선택 `minSelections`·`maxSelections`. `passingScore`는 문항 배점 합과 함께 검증되므로 문항과 같은 요청에 둔다.
- 공통 창 옵션은 3117 본체 JSON에서 최상위로 옮겨진다(서버 처리). 프런트는 옮기지 않는다.
- 문항·선택지를 별도 테이블 행으로 펼쳐야 하는지는 폐쇄망 테이블 구조 확인 후 정한다(현재 공통 함수 없음).

### P4. 저장 호출 단위

- 권장: 단일 저장 API로 보내고 서버가 테이블에 나눠 저장(트랜잭션). 프런트가 테이블별 API를 나눠 호출하면 부분 성공·순서·재시도·보상을 프런트가 맡게 된다.
- 테이블별 API가 이미 정해져 있으면 순서(게시정보 → 본체 JSON(content) → 문항 → 대상자)와 실패 시 처리를 서버와 함께 정한다.

### P5. 조회 → 편집값 복원

- `createDefaultPopup()` 위에 최상위 값·`content`·`questions`를 넣은 뒤 `toEditorPopup`으로 정리한다. `active`·`targetGroups`는 부모 state로 따로 둔다.

### P6. 가이드 공지

- 정책과 함수가 바뀌면 `guide/guideNotices.ts`에 공지한다(사용하는 쪽 조치 포함). 반입본에 함께 들어간다.

## 4. 프로세스

```
편집값 ─validate*─▶ toSaveRequest(popup, active, targetGroups) ─┬─ 최상위: 구조 분해 key/value  → 게시정보 body
                                                                ├─ active·targetGroups         → 대상자 body
                                                                └─ pickPopupFields(toSaveRequestPopup(popup), { contentKeys, questionKeys }) → 본체 JSON·문항 body
```

- 권장 방식: 저장은 단일 API(P4), 화면별 조회·표시는 위 함수로 필요한 부분만 사용.
- 가이드: 관리자 '팝업 관리 > PopupcommonComponent 가이드'의 'content·문항 가공' 탭(키 표·코드·실행기).
