# 06. 서버(zeroserver) 변경 설계 — 구현 반영 (2026-09-19 단계 3~5 완료, 2026-09-20 업스트림 Oracle 서버 위로 재적용)

기준 항목 2·3·4·5·6의 서버 구현. **2026-09-20**: 공통 베이스라인이 업스트림 `zero-rule-server` @`56bb0c5`(Spring Boot 3.4.1·cloverframework 3.0.3-SNAPSHOT·Oracle)로 바뀌었고 아래 파일은 그 위에 그대로 재적용했다. 공통 파일 수정은 `application-common.yml`(custom.wpf-popup 추가)·`application-local.yml`(popup.video, dev-user-header)·`service/core/build.gradle.kts`(jackson-databind)·`app/build.gradle.kts`(wpfDevServer 태스크)·`JndiResource.java`(환경변수 우선 분기) 5개, 모두 추가형이다. popup 관련 소스는 사용자가 직접 추가한 코드이므로 직접 수정하고, zero 프레임워크 공통 파일(보안 필터·설정·로그인)은 건드리지 않는다. 사용자 식별 어댑터는 04 문서, Oracle 매퍼 변환은 05 문서에 있다. 토큰 발급·검증 필터는 타 팀 통합 토큰 범위이므로 여기에 없다.

## 2. 처리 흐름

### 2.1 목록 — `WpfPopupService.getPopupsForUser`

1. `WpfUserResolver.resolveEmployeeNo(request)` — 실패 시 401 `WPF_UNAUTHORIZED`
2. `countActiveUser` — 0이면 403 `WPF_USER_INACTIVE`
3. `PopupMapper.selectAvailablePopups(userId, excludeCompleted=true)` — 활성·기간·대상·숨김·**완료** 판정을 SQL 한 번으로 (기준 2)
4. 템플릿 ID를 모아 `PopupService.loadPublicQuestions` 1회 (정답 제외)
5. `PopupService.toPublicResponseDto` → `WpfPopupItem.from` (WPF 비노출 필드 제거)
6. `serverTime`, `pollingIntervalSeconds`(props) 포함 응답

기존 WPF-01(`PopupService.getPopups`)은 `selectAvailablePopups(userId)` default 오버로드로 `excludeCompleted=false`를 유지해 계약이 변하지 않는다.

### 2.2 결과 — `WpfPopupService.processResults` → `WpfResultProcessor.processOne` (항목마다 REQUIRES_NEW)

| resultType | 처리 (기존 PopupService 메서드 재사용) | 응답 값 |
|---|---|---|
| CLOSED | `countActiveUserAndPopup` 확인 → `mergeDisplayAndClose` | popupStatus, completed |
| HIDDEN | hideDays 필수 → 위 + `PopupService.hidePopup` | + hiddenUntil |
| SUBMITTED | `PopupService.submitResponse(popupId, resultId, employeeNo, startedAt, answers)` → `mergeDisplayAndClose` | + responseId. **QUIZ만** totalScore/passed (SURVEY는 생략) |
| VIDEO_WATCHED | `PopupService.saveVideoProgress(...)` → `mergeDisplayAndClose` | + watchedRatio, requiredRatio |

- 처리 성공 시 같은 트랜잭션에서 `insertReceipt(ACCEPTED)`. 처리 전 `countReceipt > 0`이면 DUPLICATE(재처리 없음).
- `IllegalArgumentException`(기존 서비스의 업무 검증)은 processOne 밖으로 전파 → 트랜잭션 롤백 → `WpfPopupService`가 REJECTED로 변환. 예외를 processOne 안에서 삼키면 내부 `@Transactional` 경계에서 rollback-only가 되어 `UnexpectedRollbackException`이 나므로 이 구조를 지킨다.
- 그 외 RuntimeException → REJECTED `WPF_INTERNAL` (메시지 비노출, 로그).
- 요청 단위 `API_REQUEST_LOG`는 컨트롤러가 `logRequest`(REQUIRES_NEW)로 남기며 실패해도 응답을 막지 않는다.

### 2.3 REJECTED 코드 매핑 (`WpfPopupService.codeOf`)

| code | 기존 메시지 근거 |
|---|---|
| `WPF_NOT_ELIGIBLE` | "제출 가능한 팝업이 아닙니다", "유효한 영상 팝업이 아닙니다", "유효한 사용자 또는 팝업이 아닙니다" |
| `WPF_TYPE_MISMATCH` | "설문형 팝업만 …" |
| `WPF_INVALID_ANSWER` | 문항·선택지·답안 관련 |
| `WPF_INVALID_HIDE_DAYS` | 숨김 일수 |
| `WPF_INVALID_VIDEO` | 영상 값 |
| `WPF_INVALID_RESULT` | 그 외 |

  polling-interval-seconds: 1800   # 응답에 내려 WPF 주기 조회 간격을 서버가 통제
