# 06. 서버(zeroserver) 변경 설계

기준 항목 2·3·4·5·6을 서버에서 구현하는 방법. **기존 클래스는 재구성하지 않고 WPF 전용 패키지를 추가**한다. 사용자 식별 어댑터는 04 문서, Oracle 매퍼 변환은 05 문서에 있다. 토큰 발급·검증 필터는 타 팀 통합 토큰 범위이므로 여기에 없다.

## 2. `WpfPopupController`

```java
package server.web.api.popup.wpf;

/**
 * [역할]
 *   WPF 팝업 클라이언트 전용 API 2개.
 *     GET  /p/api/wpf/popups          — 사용자에게 지금 표시해야 할 최종 팝업 목록(공통 옵션·content·문항·선택지 포함)
 *     POST /p/api/wpf/popups/results  — 팝업 처리 결과(닫기·숨김·제출·영상 시청) 일괄 수신
 *
 * [추가 이유]
 *   기준 2: 표시 대상 판단을 서버가 끝내고 WPF는 렌더링만 하도록, 완료 팝업 제외까지 포함한 목록을 준다.
 *   기준 3: 기존 6개 API(목록/상태/숨김/제출/진행률/이벤트)를 조회 1개 + 결과 1개로 통합한다.
 *   기준 4: 실시간 이벤트·진행률 호출을 없애고 종료 시점 1회 전송을 받는다.
 *   기준 6: 사용자 식별은 요청의 userId가 아니라 WpfUserResolver가 인증 정보에서 읽은 사번으로 한다.
 *          토큰 발급·검증 자체는 타 팀 통합 토큰 필터가 담당하며 이 컨트롤러는 그 결과만 사용한다.
 *
 * [기존 구조와의 관계]
 *   기존 PopupController(/p/api/popups/**)와 PopupService는 수정하지 않는다. 이 컨트롤러는 별도 경로·별도 서비스를 쓴다.
 *   응답 날짜는 신규 DTO 필드의 @JsonFormat(ISO 8601)으로 직렬화하며, 전역 ObjectMapper 설정은 건드리지 않는다.
 *   SecurityConfig·CustomAuthenticationFilter·DefaultPublicUrls는 수정하지 않는다 (통합 토큰 필터 등록은 타 팀 작업).
 */
@Tag(name = "Popup WPF")
@RestController
@RequestMapping("/p/api/wpf/popups")
public class WpfPopupController {

    private final WpfPopupService wpfPopupService;
    private final WpfUserResolver wpfUserResolver;   // 04 문서 §3. 개발 프로파일에서는 DevHeaderWpfUserResolver

    /** 인증된 사용자의 최종 팝업 목록. 사번은 WpfUserResolver에서 얻는다(요청 파라미터 사용 금지). */
    @Operation(summary = "WPF 표시 대상 팝업 목록 조회 (공통 옵션·콘텐츠·문항 포함)")
    @GetMapping
    public WpfPopupListResponse getPopups(HttpServletRequest request) {
        String employeeNo = wpfUserResolver.resolveEmployeeNo(request);   // 실패 → WpfUnauthorizedException → 401
        return wpfPopupService.getPopupsForUser(employeeNo);
    }

    /**
     * 결과 항목 일괄 수신. 항목 단위로 독립 처리하며 한 항목의 실패가 다른 항목에 영향을 주지 않는다.
     * 요청 전체가 잘못된 경우(검증 실패)만 400을 반환하고, 항목 실패는 본문 status=REJECTED로 알린다.
     */
    @Operation(summary = "WPF 팝업 처리 결과 일괄 전송 (닫기·숨김·제출·영상)")
    @PostMapping("/results")
    public WpfResultResponse postResults(@Valid @RequestBody WpfResultRequest body, HttpServletRequest request) {
        String employeeNo = wpfUserResolver.resolveEmployeeNo(request);
        return wpfPopupService.processResults(employeeNo, body, request.getRemoteAddr());
    }
}
```

## 3. `WpfPopupService`

```java
/**
 * [역할]
 *   WPF 조회 응답 조립과 결과 요청 분배. DB 접근은 WpfPopupMapper, 유형별 결과 처리는 WpfResultProcessor에 맡긴다.
 *
 * [추가 이유]
 *   기존 PopupService는 관리자 편집·WPF 조회·채점·영상·이벤트를 한 클래스(1,083줄)에서 처리한다.
 *   기존 구조를 분해하지 않고(기준: 구조 변경 최소화) WPF 신규 계약만 담당하는 서비스를 옆에 둔다.
 *   문항 로딩·채점 규칙처럼 재사용 가능한 로직은 기존 PopupService/PopupQuestionRules의 public 메서드를 호출한다.
 *
 * [조회 규칙 — 기준 2]
 *   selectWpfAvailablePopups 한 번으로 활성·기간·대상·숨김·완료를 모두 판정한다. Java에서 추가 필터링을 하지 않는다.
 */
@Service
public class WpfPopupService {

    private final WpfPopupMapper wpfMapper;
    private final PopupService popupService;        // 기존 서비스 재사용 (loadQuestions 등은 public 위임 메서드 추가)
    private final WpfResultProcessor resultProcessor;
    private final PopupContentAssembler contentAssembler;
    private final WpfPopupProps props;              // custom.wpf-popup.polling-interval-seconds=1800

    @Transactional(readOnly = true)
    public WpfPopupListResponse getPopupsForUser(String employeeNo) {
        List<PopupEntity> popups = wpfMapper.selectWpfAvailablePopups(employeeNo);
        // 팝업마다 문항 쿼리를 반복하지 않도록 템플릿 ID를 모아 한 번에 조회 (기존 방식 유지)
        Map<Long, List<PopupQuestionDto>> questions = popupService.loadPublicQuestions(distinctTemplateIds(popups));
        List<WpfPopupItem> items = popups.stream()
                .map(p -> WpfPopupItem.from(p, contentAssembler.assemble(p), questions.getOrDefault(p.questionTemplateId(), List.of())))
                .toList();
        return new WpfPopupListResponse(OffsetDateTime.now(KST), employeeNo, props.getPollingIntervalSeconds(), items);
    }

    /**
     * 항목별로 (1) 영수증 중복 확인 → (2) 유형별 처리 → (3) 영수증 기록. 각 항목은 REQUIRES_NEW 트랜잭션.
     * 처리 중 예외는 항목 REJECTED로 바꾸고 다음 항목을 계속한다. 요청 단위 로그는 API_REQUEST_LOG에 남긴다.
     */
    public WpfResultResponse processResults(String employeeNo, WpfResultRequest body, String clientIp) {
        List<WpfResultItemResponse> out = new ArrayList<>();
        for (WpfResultItem item : body.results()) {
            out.add(resultProcessor.processOne(employeeNo, item));   // 내부에서 REQUIRES_NEW + 영수증
        }
        wpfMapper.insertApiRequestLog(...);                           // 요청 요약(항목 수·ACCEPTED/REJECTED 수)
        return new WpfResultResponse(OffsetDateTime.now(KST), out);
    }
}
```

`PopupService`에는 다음 **public 위임 메서드 2개만 추가**한다 (기존 private 로직 재사용, 본문 이동 없음):

```java
/** [WPF API 추가 — 기준 3] WpfPopupService가 정답 제외 문항을 재사용하기 위한 공개 진입점. 기존 private loadQuestions(ids,false) 위임. */
public Map<Long, List<PopupQuestionDto>> loadPublicQuestions(List<Long> templateIds) { return loadQuestions(templateIds, false); }

/** [WPF API 추가 — 기준 3] 결과 API의 SUBMITTED 처리가 기존 채점·저장 로직을 그대로 쓰기 위한 진입점.

public PopupSubmitResponseDto submitForWpf(String popupId, String resultId, String employeeNo,
                                           OffsetDateTime startedAt, List<PopupSubmitAnswer> answers) {
    return submitResponse(popupId, resultId, employeeNo, startedAt, answers);
}
```

## 4. `WpfResultProcessor` — 유형별 처리

```java
/**
 * [역할] 결과 항목 1건을 유형(resultType)에 따라 처리하고 항목 응답을 만든다.
 * [추가 이유 — 기준 3·4] 기존에는 hide/responses/video-progress/events 4개 API가 각각 처리하던 것을
 *   한 진입점에서 분배한다. 기존 PopupService의 hidePopup/submitResponse/saveVideoProgress/recordPopupEvent는
 *   그대로 두고, 여기서는 "토큰 사용자 + 종료 시점 1회" 규칙에 맞는 신규 매퍼 구문을 사용한다.
 * [트랜잭션] processOne은 REQUIRES_NEW. 한 항목 실패가 다른 항목 커밋에 영향을 주지 않는다.
 * [멱등성] WPF_RESULT_RECEIPT.RESULT_ID 유니크. 이미 있으면 DUPLICATE 반환, 재처리하지 않는다.
 */
@Service
public class WpfResultProcessor {

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public WpfResultItemResponse processOne(String employeeNo, WpfResultItem item) {
        if (wpfMapper.existsReceipt(item.resultId())) {
            return WpfResultItemResponse.duplicate(item);
        }
        try {
            WpfResultItemResponse res = switch (item.resultType()) {
                case CLOSED        -> handleClosed(employeeNo, item);
                case HIDDEN        -> handleHidden(employeeNo, item);
                case SUBMITTED     -> handleSubmitted(employeeNo, item);
                case VIDEO_WATCHED -> handleVideo(employeeNo, item);
            };
            wpfMapper.insertReceipt(item.resultId(), employeeNo, item.popupId(), item.resultType(), "ACCEPTED", null);
            return res;
        } catch (IllegalArgumentException ex) {                 // 기존 서비스의 업무 검증 예외 규약 재사용
            wpfMapper.insertReceipt(item.resultId(), employeeNo, item.popupId(), item.resultType(), "REJECTED", codeOf(ex));
            return WpfResultItemResponse.rejected(item, codeOf(ex), ex.getMessage());
        }
    }

    /** CLOSED: 활성 사용자·팝업 확인 후 표시·닫기 정보만 갱신. displayedAt이 있으면 표시 횟수 +1. */
    private WpfResultItemResponse handleClosed(String emp, WpfResultItem it) {
        requireActiveUserAndPopup(emp, it.popupId());
        wpfMapper.mergeDisplayAndClose(emp, it.popupId(), kst(it.displayedAt()), kst(it.closedAt()));   // MERGE, 완료 상태 유지
        return WpfResultItemResponse.accepted(it, wpfMapper.selectStatus(emp, it.popupId()));
    }

    /** HIDDEN: CLOSED 처리 + 숨김 기간. 만료 시각은 서버 시각 기준(SYSTIMESTAMP + hideDays). */
    private WpfResultItemResponse handleHidden(String emp, WpfResultItem it) {
        if (it.hideDays() == null || it.hideDays() < 1 || it.hideDays() > 3650)
            throw new IllegalArgumentException("숨김 일수는 1~3650이어야 합니다.");
        requireActiveUserAndPopup(emp, it.popupId());
        wpfMapper.mergeDisplayAndClose(emp, it.popupId(), kst(it.displayedAt()), kst(it.closedAt()));
        wpfMapper.mergeHide(emp, it.popupId(), it.hideDays());                                      // 기존 upsertPopupHide의 MERGE 판
        return WpfResultItemResponse.accepted(it, wpfMapper.selectStatus(emp, it.popupId()));
    }

    /**
     * SUBMITTED: 기존 PopupService.submitForWpf에 위임 (노출 자격 재검사·문항 검증·QUIZ 채점·응답 upsert·완료 표시).
     * SURVEY는 채점하지 않으므로 응답에서 totalScore/passed를 생략한다(참조 저장소 STRUCTURE_REVIEW P0 반영).
     * SURVEY 완료 규칙: 제출 즉시 COMPLETED — 기존 submitResponse는 passedYn 기준으로 완료를 표시하므로,
     * SURVEY는 위임 후 markCompletedForSurvey(MERGE COMPLETED_YN='Y')를 한 번 더 호출한다.
     */
    private WpfResultItemResponse handleSubmitted(String emp, WpfResultItem it) { ... }

    /**
     * VIDEO_WATCHED: 진행률을 종료 시점 1회 반영. 비율 계산·완료 판정은 기존 saveVideoProgress와 동일 규칙
     * (watched/duration 4자리 내림, requiredRatio 기본 1.0, 최대값 유지·완료 되돌리지 않음).
     */
    private WpfResultItemResponse handleVideo(String emp, WpfResultItem it) { ... }
}
```

## 5. `WpfPopupMapper.xml` 주요 구문

| ID | 내용 | 원본 참조 |
|---|---|---|
| `selectWpfAvailablePopups` | 05 문서 §4.4. 완료 제외 포함. 콘텐츠 컬럼 개별 반환 | `selectAvailablePopups` |
| `mergeDisplayAndClose` | USER_POPUP_STATUS MERGE. displayedAt 있으면 FIRST(COALESCE)/LAST/COUNT+1, closedAt 갱신, 완료면 상태 COMPLETED 유지 | `upsertPopupEvent` |
| `mergeHide` | HIDDEN_FROM/UNTIL 설정 | `upsertPopupHide` |
| `mergeVideoProgress` | GREATEST 유지·완료 되돌리지 않음 | `upsertVideoProgress` |
| `markCompletedForSurvey` | COMPLETED_YN='Y', COMPLETED_AT=COALESCE(기존, SYSTIMESTAMP) | `markPopupCompleted` 변형 |
| `selectStatus` | 응답용 popupStatus/completed/completedAt/hiddenUntil | `selectPopupStatuses` 1건 |
| `existsReceipt` / `insertReceipt` | WPF_RESULT_RECEIPT | 신규 |
| `insertApiRequestLog` | API_REQUEST_LOG | 신규 (미사용 테이블 활용) |
| `countActiveUserAndPopup` | 기존 구문과 동일 SQL | 재사용을 위해 복제하지 않고 기존 `PopupMapper` 호출 |

## 6. `WpfApiExceptionHandler`

```java
/**
 * [역할] WPF 컨트롤러(WpfPopupController)에서 발생한 예외를 {code, message, timestamp} JSON으로 변환.
 * [추가 이유] 기존 프레임워크 예외 응답(CLNewApiResponse/msgId 체계)은 관리자 웹 규약이다.
 *   WPF는 단순 코드 체계가 필요하고, 기존 ApiExceptionHandler를 바꾸면 다른 API 응답이 달라지므로
 *   assignableTypes로 범위를 WPF 컨트롤러에 한정한 별도 어드바이스를 둔다.
 *   토큰 검증 실패(401)는 타 팀 통합 토큰 필터가 컨트롤러 진입 전에 응답하므로 여기서 다루지 않는다.
 */
@RestControllerAdvice(assignableTypes = WpfPopupController.class)
public class WpfApiExceptionHandler {
    @ExceptionHandler(MethodArgumentNotValidException.class) → 400 WPF_BAD_REQUEST
    @ExceptionHandler(IllegalArgumentException.class)        → 400 WPF_BAD_REQUEST
    @ExceptionHandler(WpfUnauthorizedException.class)        → 401 WPF_UNAUTHORIZED (WpfUserResolver가 사번을 못 얻음)
    @ExceptionHandler(WpfUserInactiveException.class)        → 403 WPF_USER_INACTIVE
    @ExceptionHandler(Exception.class)                       → 500 WPF_INTERNAL (메시지 비노출, 로그만)
}
```
