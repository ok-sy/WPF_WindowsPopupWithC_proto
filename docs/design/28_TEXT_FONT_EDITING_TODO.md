## 2. 방식 비교와 결정

| 방식 | 판단 |
| --- | --- |
| 편집기 HTML을 그대로 저장·전달 | 미채택. 편집기 형식이 팝업 전체 계약이 되고, 웹 표시·WPF 파싱·서버 정리 중 한 곳만 어긋나도 위험이 생긴다 |
| 문단·Run JSON 저장, 편집기는 기존 CKEditor 사용 | **채택 방향**. HTML은 편집기 입출력 경계에서만 다룬다 |
| Markdown | 미채택. 색·크기·글꼴을 표현할 수 없고 TEXT에서 제거한 기능 |
| XAML·RTF 문자열 | 미채택. 웹 편집·미리보기 불가, 문자열 로드 위험 |
| 미리 정한 강조 스타일만 제공 | 미채택. 요구(글꼴·색상·구간별 변경)를 줄이는 선택이므로 허용 값 안에서 직접 선택하게 한다 |

채택 방향에서도 변환 작업은 줄지 않는다. 필요한 변환은 다음과 같고, 장점은 HTML을 다루는 위치를 편집기 경계로 모으는 데 있다.

| 변환 | 위치(후보) |
| --- | --- |
| 편집기 HTML → 문단·Run JSON (허용 서식만 추출) | 서버(저장 시) 또는 관리자 웹. 서버는 클라이언트 입력을 신뢰하지 않고 Run JSON 값을 다시 검증 |
| 문단·Run JSON → 편집기 HTML (재편집) | 관리자 웹 또는 서버. text는 반드시 이스케이프 |
| 문단·Run JSON → WPF Inlines | WPF |
| 문단·Run JSON → 관리자 미리보기 | 관리자 웹. React 요소로 생성하고 innerHTML을 쓰지 않음 |
| 문단·Run JSON → 일반 문자열(plainText) | 서버(저장 시 파생) |

글자 서식은 줄바꿈 이후에도 해당 글자에 유지하고, 정렬은 문단에 적용한다.

## 4. 데이터 구조 — 문단·Run JSON

본문을 문단 배열로 저장하고, 문단 안에는 같은 서식의 연속된 글자 묶음(Run)을 순서대로 저장한다.
서식이 있는 글자뿐 아니라 일반 글자와 공백도 모두 포함한다.
Run의 text를 순서대로 연결한 결과가 문단의 본문이며, Run 경계에서 공백이나 줄바꿈을 자동 추가하지 않는다.
동일한 text 값은 고유 식별자가 아니다. 편집기의 선택 위치로 구간을 구분한다.

아래는 구조 설명용 예시이며 필드명·단위·기본값은 최종 계약이 아니다.

```json
{
  "content": {
    "plainText": "확인 후 다시 확인하세요",
    "textBlocks": [
      {
        "alignment": "LEFT",
        "runs": [
          { "text": "확인 후 다시 " },
          { "text": "확인", "bold": true, "color": "#DC2626" },
          { "text": "하세요" }
        ]
      }
    ]
  }
}
```

- 저장 위치: textBlocks는 기존 `POPUP_CONTENT.CONTENT_OPTIONS`(CLOB JSON)에 둔다. 1차 범위는 **DB 컬럼 변경이 없다**.
- 기준 데이터: textBlocks가 있으면 그것이 기준이다. plainText는 서버가 저장 시 textBlocks에서 파생해 기존 `CONTENT_BODY`(CLOB)에 저장하며 관리자가 따로 수정하지 않는다.
- 호환: textBlocks가 없는 기존 데이터·구버전 응답은 지금처럼 plainText로 표시한다.
- 편집기는 선택 범위에 따라 Run을 분할하고, 인접한 Run의 유효 서식이 같으면 합친다.

- [x] 문단 나누기·문단 내부 줄바꿈·빈 문단·연속 공백의 저장 규칙 확정.
- [x] 서식 우선순위: 구간 서식 → 본문 기본 서식(bodyFontSize) → 앱 기본값.
- [x] 글자 크기 단위·허용 목록, 색상 팔레트, 글꼴 목록, 최대 글자·문단·Run 수 결정.
- [x] 허용되지 않은 값의 처리(저장 거부 / 기본값 대체) 결정.

## 7. 보안

- 관리자 웹은 저장 데이터를 innerHTML(dangerouslySetInnerHTML)로 표시하지 않는다. Run JSON을 React 요소로 만든다.
- Run JSON → 편집기 HTML 생성 시 text를 반드시 이스케이프한다. JSON 저장이라도 이 단계에서 이스케이프를 빠뜨리면 저장형 XSS가 된다.
- 서버는 관리자 UI를 거치지 않은 API 입력도 같은 규칙으로 검증한다(허용 키·서식 값·길이).
- WPF는 Run JSON 값을 허용 목록 값만 Inline 속성으로 변환하며 HTML/XAML 문자열을 로드하지 않는다.
- 일반 조회·표시 경로에서 HTML을 다루지 않으므로 HTML 처리 범위가 편집기 경계로 줄어든다. HTML 위험이 사라진다는 뜻은 아니다.

## 9. 개발 결정 전 왕복 검증 (우선)

작은 본문 하나로 작성 → 저장 → 다시 편집 → WPF 표시를 왕복시켜 실제 구현 부담을 확인한다.

### 9.1 수행 방법 (2026-10-09, 저장소 밖 임시 코드)

- 관리자 웹이 쓰는 실제 빌드(`@cp949/ckeditor5-custom-build` 0.0.15, CKEditor 5 v34.1.0)를 WebView2 페이지에 올리고 허용 목록(색 4종, 크기 12·14·16·20·24px, 글꼴 2종, 정렬 3종)으로 설정.
- 편집 모델로 본문을 만들고 색·크기·글꼴은 사용자가 구간 선택 후 누르는 것과 같은 편집기 명령(`fontColor`·`fontSize`·`fontFamily`)으로 적용.
- `getData()` HTML → Run JSON 변환 → Run JSON → HTML 생성 → `setData()` → `getData()` → Run JSON 재변환 후 비교.
- Run JSON을 WPF `TextBlock` Inlines(문단별 TextAlignment, `
`→LineBreak)로 렌더링해 이미지로 확인.
- 변환기는 검증용 JavaScript로 작성했다. 운영 구현 위치(서버/관리자 웹)는 §2 기준으로 별도 결정한다.

### 9.2 결과

- [x] Run JSON 왕복 일치: 한글, 앞뒤·연속 공백, 빈 문단, 문단 내부 줄바꿈(Shift+Enter→`<br>`), 정렬, 굵게·기울임·밑줄, 색·크기·글꼴 혼합 구간, `<script>`·`&`·따옴표 문자열이 재편집 후 동일한 Run JSON으로 돌아왔다.
- [x] WPF 표시: 색·크기·글꼴·굵게·기울임·밑줄·정렬·줄바꿈·공백이 의도대로 표시되고 `<script>` 문자열은 글자 그대로 표시되었다.
- [x] 비허용 입력: 정렬 justify, 팔레트 밖 색(hsl), 18px, 비허용 글꼴, `img`·`a`·`script`, 제목 태그를 넣은 HTML에서 허용 서식만 남았다.
- [x] HTML 문자열은 왕복 후 같지 않았다(`&nbsp;` 위치, 태그 중첩 순서, `"` 이스케이프). 의미는 같으므로 **비교·저장 기준은 Run JSON이어야 하며 HTML을 저장하지 않는 결정이 맞다**.

### 9.3 확인된 규칙·주의점 (개발 시 반영)

- [x] 빈 문단은 편집기에서 `<p>&nbsp;</p>`로 나온다. 공백 하나뿐인 문단과 구분되지 않으므로 "공백 하나뿐인 문단 = 빈 문단"으로 정한다. WPF는 빈 문단에도 한 줄 높이를 유지해야 한다.
- [x] `&nbsp;`는 일반 공백으로 저장한다. 재편집 HTML 생성 시 앞뒤·연속 공백은 `&nbsp;`로 되돌려야 접히지 않는다.
- [x] 글꼴: 이름에 공백이 있는 글꼴은 편집기 설정에서 따옴표로 감싸지 않으면 **오류 없이 적용되지 않는다**(`'맑은 고딕', 'Malgun Gothic', sans-serif`). Run JSON에는 CSS 문자열 대신 글꼴 ID(예: `MALGUN_GOTHIC`)를 저장하고 웹·WPF가 각각 매핑한다. WPF는 CSS 일반 계열명(sans-serif 등)과 따옴표를 쓰지 않는다.
- [x] 크기: 숫자 옵션의 편집기 값은 `'20px'` 문자열이다. Run JSON은 숫자(px)로 저장하고 변환기에서 매핑한다.
- [x] 이 빌드의 기본 툴바에는 HTML 소스 편집(sourceEditing)·제목·표·이미지·링크·목록·코드 등이 포함되어 있다. 팝업 전용 편집 컴포넌트는 툴바를 직접 정의하고 불필요한 플러그인은 `removePlugins`로 제외한다.
- [x] 붙여넣기 등으로 들어온 내용 처리: `script`·`style`은 내용째 제거, 제목·인용 블록은 글자를 보존하며 일반 문단으로 변환, 이미지 제거, 링크는 글자만 보존, 허용 밖 색·크기·글꼴·정렬은 제거. (검증 중 script 내용이 글자로 남는 문제와 제목 글자가 사라지는 문제를 발견해 위 규칙으로 수정)
- [x] 허용 밖 값을 "제거 후 저장"할지 "저장 거부"할지 결정. 붙여넣기는 제거, API 직접 입력은 거부가 후보.

## 10. SURVEY·QUIZ (1차 제외, 공통 구조만 준비)

- 서식 데이터 모델·검증·편집 컴포넌트·WPF 렌더링을 유형별로 재사용할 수 있게 공통화한다.
- 설명: content 경로(CONTENT_OPTIONS)라 DB 변경 없이 확장 가능.
- 문항·선택지: `POPUP_QUESTION`·선택지 테이블에 JSON 저장 컬럼이 없어 컬럼 변경이 필요하다. 파생 일반 문자열은 기존 VARCHAR2 제한(문항 제목 1000자·설명 2000자·선택지 1000자)을 따르므로 서식 제외 글자 수 검증이 필요하다. 저장 방식은 테이블 구조를 확인한 뒤 결정한다.
- 선택지에서 여러 문단을 지원하지 않는다면 등록 시 제한하거나 내용을 보존하며 줄바꿈으로 합친다. 일부 문단만 사용하지 않는다.
- 질문·선택지 ID, 응답 값, 정답·점수·채점 규칙, 결과·통계는 일반 문자열과 ID를 사용하고 표시 서식과 분리한다.
- 적용 시 행 높이·체크 표시·클릭 영역·스크롤, 단일/복수 선택·필수·채점·제출, VIDEO+QUIZ 회귀를 검증한다.

## 11. 관리자 편집 UI — 서식 버튼 + 우클릭 메뉴

선택한 글자에서 우클릭하면 색상 팔레트와 글꼴 설정 메뉴를 표시한다.
기능 발견성과 키보드 접근을 위해 입력란의 '서식' 버튼으로도 같은 메뉴를 연다.

- [ ] 메뉴 후보: 색상 팔레트·색상 초기화, 글꼴, 크기, 굵게·기울임·밑줄, 서식 지우기.
- [ ] 글자 선택 후 메뉴를 열면 해당 선택 구간에만 적용.
- [ ] 선택 없이 메뉴를 열면 커서 이후 새로 입력할 글자에 적용. 기존 본문 전체에 자동 적용하지 않음.
- [ ] 우클릭 및 메뉴 항목 클릭 시 선택 범위·커서 위치를 보존하고 서식 적용 후 편집 위치 복귀.
- [ ] 여러 서식이 섞인 구간을 선택했을 때 메뉴의 혼합 상태 표시 정의.
- [ ] 서식 지우기는 선택 구간의 서식을 기본값으로 되돌리며 글자 내용은 보존.
- [ ] 서식 편집 영역 안에서만 사용자 정의 우클릭 메뉴를 적용하고 바깥은 브라우저 기본 메뉴 유지.
- [ ] 복사·잘라내기·붙여넣기와 기본 단축키 유지. 붙여넣기한 외부 서식은 허용 값으로 정리.
- [ ] 키보드로 메뉴 열기·이동·적용·닫기, Esc로 취소 시 선택 범위 유지.
- [ ] 화면 경계에서 메뉴 잘림 방지, 바깥 클릭 시 닫기, 실행 취소·다시 실행 검증.

## 12.1 1차 구현 결과 (2026-10-09)

- 계약: content.textBlocks = [{ alignment, runs: [{ text, bold, italic, underline, color, size, font }] }]. 허용 값: 색은 대문자 #RRGGBB 형식이면 모두 허용(팔레트 제한 없음, 편집기 팔레트 8색 #111827 #6B7280 #DC2626 #EA580C #CA8A04 #16A34A #2563EB #7C3AED는 선택지), 크기 12·14·16·18·20·24·28·32px, 글꼴 ID MALGUN_GOTHIC·GULIM·DOTUM·BATANG, 정렬 LEFT·CENTER·RIGHT. 최대 500문단·2000구간·20000자. 상세는 인터페이스 계약 8.1.
- 서버: `PopupRichText.java`가 구조·허용 값·제한을 검증하고(허용 밖 값은 저장 거부, TEXT 외 유형의 textBlocks 거부) plainText를 textBlocks에서 파생해 CONTENT_BODY에 저장한다. textBlocks는 CONTENT_OPTIONS에 저장되며 DB 변경은 없다.
- 관리자 웹: `PopupRichTextEditor.tsx`(팝업 전용 CKEditor 툴바: 굵게·기울임·밑줄·글자색·크기·글꼴·정렬·서식 지우기·실행 취소/다시 실행)와 `popupRichText.ts`(HTML↔Run 변환, 허용 값, 붙여넣기 정리). 변경 시 textBlocks와 파생 plainText를 함께 갱신. 서식 본문이 없는 기존 데이터는 plainText를 서식 없는 문단으로 열어 편집한다. 미리보기는 React 요소로 표시한다(innerHTML 미사용).
- WPF: `PopupTextBlockDto`·`PopupRichText.cs`가 문단별 TextBlock Inlines로 표시. 허용 밖 서식 값은 무시하고 글자만 표시, 빈 문단은 한 줄 높이 유지, 큰 글자 구간은 줄 높이를 늘림. bodyFontSize는 문단 기본 크기에 적용되고 구간 크기가 우선한다. textBlocks가 없으면 기존 plainText 표시.
- Demo: TEXT 샘플에 서식 본문(10문단) 추가, 옵션 창에서 textBlocks JSON 편집(서버와 같은 검증·plainText 파생, 비우면 일반 본문 사용), 시나리오 요약에 서식 본문 문단 수 표시.
