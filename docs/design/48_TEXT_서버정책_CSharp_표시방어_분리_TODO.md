## 배경과 확정 방향

TODO36은 C# 화이트리스트를 유지했으나, 서버와 C#이 같은 허용 목록을 각각 관리하면 한쪽 변경 누락으로 저장 결과와 표시 결과가 달라질 수 있다. 예를 들어 서버에서 크기 22를 허용해도 C# 목록에 없으면 정상 저장한 서식이 조용히 무시된다. 중복 목록을 유지하는 편의보다 이 불일치 위험을 우선한다.

- 서버는 TEXT 서식의 허용 정책을 검증한다. C# 렌더러는 표시 변환과 최소한의 예외 방어를 담당한다.
- Demo는 운영 시점에 제거될 대상이다. Demo 샘플의 검증 우회나 옵션 편집기의 목록 재사용을 운영 C# 화이트리스트 유지 근거로 사용하지 않는다.
- DB 직접 수정 가능성도 서버와 동일한 정책 목록을 C#에 복제할 근거로 사용하지 않는다. 잘못된 입력에 대한 표시 방어는 별도로 남긴다.
- TODO36의 당시 검토 이력은 보존하되, 향후 구현 방향은 이 TODO48이 대체한다.
- 이전 배포 버전 호환이나 단계별 배포 순서를 위한 별도 구현은 요구하지 않는다.

## 책임 구분

| 항목 | 서버 | C# 렌더러 |
|---|---|---|
| 글자 크기 | 허용 크기 정책 검증 | 동일한 이산 목록 검사 제거. 유한값·WPF 적용 가능 범위 및 레이아웃 안전 범위만 검사 |
| 색상 | API 색상 형식·정규화 정책 검증 | 정책용 대문자 강제 제거. 지원하는 색상 표현을 안전하게 변환하고 실패 시 기본색 유지 |
| 글꼴 | 허용 글꼴 ID 검증 | ID → WPF 글꼴명 변환 유지. 별도 허용 ID 검사는 중복하지 않고 미지원 ID는 기본 글꼴 사용 |
| 정렬 | 허용 정렬 값 검증 | WPF enum 변환 및 알 수 없는 값의 기본 정렬 유지 |
| null·비정상 입력 | 저장 단계 계약 검증 | 표시 가능한 본문 보존과 서식 기본값 처리 |

서버의 현재 허용 값 자체를 확대하는 과제가 아니다. WPF가 파싱할 수 있다는 이유만으로 임의 색상 표현·객체를 모두 허용하지 않는다. 글꼴 ID 매핑은 필요한 표현 의존성으로 남으며 서버의 새 ID 추가 시 매핑 검토가 필요하다는 점을 명시한다.

## 구현 TODO

- [x] **48-1 호출 경로와 중복 검사 분리**: `PopupRichText.cs`와 호출부에서 정책 검사·WPF 변환·예외 방어를 구분한다. Demo 참조는 빌드 영향만 확인하고 유지 논증에서 제외한다. Demo 전체 제거는 이 과제의 범위가 아니다.
- [x] **48-2 크기 목록 검사 제거**: 렌더러의 `Sizes.Contains`를 제거한다. NaN·Infinity·0·음수·과대값에 대한 기술적 안전 범위와 기본값 동작을 정의하고 근거를 기록한다. 서버의 허용 크기를 그대로 복제한 범위를 만들지 않는다. 안전 범위 변경이 필요한 서버 계약 확장은 별도 영향 확인 대상으로 명시한다.
- [x] **48-3 색상 변환 방어**: 대문자 전용 정책 검사를 제거하고, 지원하는 색상 형식을 예외 없이 변환한다. 유효한 소문자 색상도 동일하게 표시하며 변환 실패 시 해당 색상만 기본값으로 처리한다.
- [x] **48-4 필수 변환 유지**: 글꼴 ID 매핑·정렬 변환·null 처리를 유지한다. 미지원 글꼴 ID와 알 수 없는 정렬은 기본값으로 표시한다. 매핑 누락 위험을 계약 검증 항목으로 남긴다.
- [x] **48-5 잘못된 입력 처리 경계**: DTO 역직렬화 이전의 JSON 타입 오류와 서식 값 변환 실패를 구분한다. 본문을 읽을 수 있으면 잘못된 서식만 기본값으로 처리하도록 검토·구현하고, 본문 자체를 읽을 수 없는 입력의 기존 오류 처리를 명시한다. 팝업 전체가 조용히 누락되는 동작을 정상 fallback으로 간주하지 않는다.
- [x] **48-6 회귀·계약 검증**: 아래 검증 기준을 실제 테스트로 확인하고 실행 환경·결과를 기록한다. 단순히 기존 화이트리스트 테스트를 삭제하는 것으로 완료하지 않는다.
- [x] **48-7 문서 정합성**: TODO36의 과거 유지 결론과 TODO48의 새 방향을 구분하고 코드 주석을 갱신한다. TODO28·TODO46 및 ALL/MINIMAL·인터페이스 문서를 검토하여 서버 허용 정책과 클라이언트 표시 방어를 혼동하지 않도록 정리한다. 최소 제공 범위는 확대하지 않는다.

## 검증 및 완료 기준

- 현재 서버가 허용하는 모든 TEXT 서식이 기존과 동일하게 표시된다. 기울임 여백·줄바꿈·빈 문단·plainText 표시도 유지한다.
- 렌더러 단위 검증에서 현재 서버 목록에 없지만 기술적 안전 범위 안인 크기(예: 22)를 전달했을 때 C# 정책 목록 때문에 무시하지 않는다. 이는 서버가 현재 22를 허용한다는 의미가 아니다.
- 잘못된 색상·비정상 크기·미지원 글꼴·정렬·null은 정의한 기본값으로 처리하고 표시 가능한 본문을 보존한다.
- JSON 타입 오류와 값 오류의 처리 경계 및 남은 제한이 문서와 테스트에서 일치한다.
- 서버 글꼴 ID와 WPF 매핑의 대응을 검증한다. 테스트에 또 다른 수동 허용 목록을 복제하지 않고 실제 정의를 대조하는 방법을 우선한다.
- Demo의 존재나 향후 제거와 무관하게 운영 표시 책임이 성립한다.
- TODO48 구현·검증 전까지 기존 C# 검사는 현 상태이며, 문서 등록만으로 제거 완료로 표시하지 않는다. → 2026-10-14 구현·검증 완료(아래 결과).

## 구현 결과 (2026-10-14)

| 항목 | 결정·구현 |
|---|---|
| 48-1 경로 분리 | `PopupRichText.cs`는 WPF 변환·표시 방어만 담당. Demo 옵션 창의 저장 검증 목록(크기·글꼴·대문자 색)은 `DemoOptionsWindow`에 Demo 전용 사본으로 이동(운영 시점 Demo와 함께 제거). 렌더러 정책 목록 `Sizes`·`IsAllowedColor` 삭제 |
| 48-2 크기 | `Sizes.Contains` 제거. 안전 범위 **1~200 DIP**(유한값). 0·음수·NaN·Infinity는 WPF FontSize 예외, 200 초과는 팝업 최대 폭에서 한 줄 배치가 무너지는 레이아웃 한계로 정의. 범위 밖은 해당 구간만 본문 기본 크기. 서버 허용 크기(12~32)의 복제가 아니며, 서버가 200을 넘는 크기를 허용하도록 계약을 넓히면 이 범위를 함께 확인 |
| 48-3 색 | 대문자 강제 제거. `#RRGGBB` 대소문자 무관을 예외 없이 직접 변환(`TryParseColor`), 실패하면 그 구간만 기본 색. `#AARRGGBB`·이름·짧은 형식은 변환하지 않음(서버 계약 형식만 지원) |
| 48-4 필수 변환 | 글꼴 ID → WPF 글꼴 매핑, 정렬 enum 변환, null 처리 유지. 매핑 없는 ID·알 수 없는 정렬은 기본값. 서버 `FONTS`와 WPF 매핑·관리자 웹 `RICH_FONTS` ID는 행동 검증이 원본 파일을 읽어 대조 |
| 48-5 입력 경계 | `textBlocks`만 `LenientTextBlocksConverter`로 직접 읽음. 서식 값의 JSON 타입 오류(alignment·bold·italic·underline·color·size·font)는 그 값만 기본값, null 문단·구간은 건너뜀. 글자를 읽을 수 없는 구조 오류(배열·객체 아님, runs 누락, text가 문자열 아님)는 일부 글자만 빠진 서식 본문 대신 서식 본문 전체를 쓰지 않고 서버 파생 `plainText` 표시. plainText 등 다른 content 값 자체의 타입 오류는 기존과 같이 content 변환 오류(팝업 조회 오류 처리, 복구 루프 제외)로 남는 제한 |
