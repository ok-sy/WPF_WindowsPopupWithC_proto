## 1. 화면 ID 및 유형

| 화면 ID | 유형 | 수신 화면에서 확인되는 주요 요소 |
|---|---|---|
| PU001P01 | TEXT | 제목·텍스트 스크롤 영역·나중에 보기·확인 |
| PU001P02 | IMAGE | 제목·이미지 스크롤 영역·나중에 보기·확인 |
| PU001P03 | VIDEO | 제목·영상/재생바·나중에 보기·확인(완료 전 비활성 예시) |
| PU001P04 | QUIZ | 제목·단일선택/객관식·나중에 보기·제출·결과 안내 |
| PU001P05 | SURVEY | 제목·단일/복수 선택·주관식·나중에 보기·제출·완료/미응답 안내 |
| PU001P06 | VIDEO+QUIZ | 제목·영상·하단 퀴즈·나중에 보기·제출 |

## 2. 공통 화면 구조

- **Header 고정:** 관리자 입력 제목을 표시하는 영역.
- **Content 스크롤:** 유형별 본문/이미지/영상/문항을 배치. 길어질 경우 스크롤 처리.
- **Footer 고정:** 왼쪽 `나중에 보기`, 오른쪽 `확인` 또는 `제출`. (2026-11-04 WPF·관리자 미리보기 반영)
- **완료 조건:** VIDEO/QUIZ/VIDEO+QUIZ 등은 조건 충족 전 버튼 비활성 예시가 있음. 유형별 완료 기준은 아래와 기존 확정 정책을 함께 확인.
- **재노출:** 나중에 보기 후 재표시 시간은 화면에 설명이 있으나 사진만으로 최종 서버 정책을 덮어쓰지 않음.

## 3. 유형별 확인 및 검증 항목

### PU001P01 — TEXT
- 관리자 입력 제목·서식 포함 텍스트 표시, 내용 영역 스크롤.
- 확인/나중에 보기 클릭 시 결과 API 및 후속 상태 확인.
- RichText 저장→DB→재조회→WPF 렌더링에서 한글·줄바꿈·들여쓰기·Footer 접근성 검증.

### PU001P02 — IMAGE
- 이미지 영역의 스크롤, 고정 Header/Footer, 확인/나중에 보기.
- 현행 `FIT_TO_IMAGE`, `ADAPTIVE`, `ORIGINAL`, `FULLSCREEN` 모드와 사진의 스크롤 예시를 비교.
- 모든 모드에서 스크롤이 필수라는 의미로 확대 해석하지 않음.

### PU001P03 — VIDEO
- 영상 재생 중 확인 버튼 비활성, 영상 종료 후 확인 활성 예시.
- 재생바·재생 제어 허용 여부·완료율 정책은 기존 계약과 대조.
- 실제 영상 재생·종료·나중에 보기·Overlay·재생 오류 상태 검증.

### PU001P04 — QUIZ
- 단일선택 O/X 및 객관식 문항, 전 문항 응답 전 제출 비활성 예시.
- 화면 하단 **커트라인형/만점형/참여형** 결과 안내 사례를 별도 구분.
- 사진의 예시에는 정답 수·전체 문항 수 및 다시 풀기/확인 알림이 나타남. **참여형은 정답 개수와 완료 안내 후 확인 종료**라는 후속 협의 내용을 우선 대조하고, API/채점 구현을 이 문서만으로 수정하지 않음.
- 점수/합격 여부의 화면 표시와 Agent 결과 전송은 서로 다른 책임으로 검토.

### PU001P05 — SURVEY
- 단일선택, 복수선택, 주관식 입력 및 필수 응답 예시.
- 미응답 시 `설문조사 답변에 체크해주세요` 취지의 안내, 제출 후 완료 안내와 확인 종료.
- 복수선택 최소·최대 수 및 주관식 공백/필수 판정은 기존 확정 정책과 비교.

### PU001P06 — VIDEO+QUIZ
- 영상 위·퀴즈 아래 배치, 각 영역 스크롤/재생 제어.
- **영상 재생 완료 및 퀴즈 문항 응답**을 함께 고려한 제출 활성 예시.
- 영상 시청 완료 기준·퀴즈 채점/재응시·결과 전달은 기존 VIDEO/QUIZ 계약과 대조.
- 영상/퀴즈 중 하나만 충족한 경우, 영상 재생 실패 시의 동작은 추가 확인.

## 4. 현행 구현 대조 원칙

| 구분 | 처리 |
|---|---|
| 사진에서 직접 확인되는 UI | 수신 요구사항으로 기록하고 WPF/관리자 미리보기와 비교 |
| 사진 글자가 흐리거나 해석이 갈리는 조건 | **확인 필요**, 임의 정책 확정 금지 |
| 기존 확정 정책과 다른 서술 | 충돌 후보로 등록하고 별도 승인 후 반영 |
| 구현 여부 | 코드·자동 테스트·실화면 검증을 분리해서 판정 |
| 결과 API | `deliveryId`, `resultType`, 점수/합격 정보 등 기존 계약과 비교하되 이 문서만으로 계약 변경 금지 |

1. 원본 PPT/고해상도 캡처 확보 후 작은 글씨·Description/Check Points 대조.

3. 확정/부분 일치/정책 충돌/실화면 미검증으로 분류.
4. R1 로컬 관리자 웹→서버→원격 개발 DB→WPF 왕복에서 6유형 검증.
5. 차이 발견 시 기존 활성 작업에 연결해 수정 여부를 별도 승인.
