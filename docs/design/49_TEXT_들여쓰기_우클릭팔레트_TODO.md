## 요구사항과 적용 범위

1. CKEditor에서 문단을 들여쓰면 해당 `p`에 왼쪽 여백 40px을 적용하고, 저장·재편집·웹 미리보기·WPF 팝업에서도 유지한다.
2. 기존 사용자 정의 우클릭 서식 메뉴를 유지하고, 참고 이미지처럼 색상 팔레트를 펼친 격자와 글꼴·크기·굵게·기울임·밑줄 설정을 한 패널에서 제공한다. 색상 선택을 위해 추가 드롭다운을 열지 않도록 한다.

우클릭 폐기 및 CKEditor 선택 툴바로 대체하는 이전 초안은 취소한다. 드래그는 서식을 적용할 글자를 선택하는 동작으로 유지하며, 선택만으로 패널을 자동으로 띄우는 기능은 이번 확정 요건에 포함하지 않는다. 참고 이미지는 패널 배치의 기준이며, 사진 속 글꼴명·크기 10·색상 개수와 정확한 색상값까지 신규 허용 정책으로 확정한 것은 아니다.

`margin: 40px`은 상하좌우 여백까지 바꾸므로 요구사항의 들여쓰기는 **`margin-left: 40px`**으로 해석한다. 문단 전체를 들여쓰며 첫 줄에만 적용하는 `text-indent`와 구분한다. 40px은 첫 들여쓰기 기준이고, 반복 입력 정책은 아래 확인 항목으로 남긴다.

적용 대상은 현재 TEXT 본문의 `content.textBlocks`와 해당 편집·표시 경로다. SURVEY·QUIZ의 문항·선택지에 서식을 새로 적용하는 범위는 포함하지 않는다.

## 기존 기능 전체 유지

사진에 보이지 않는 기능도 제거하지 않는다. 우클릭 패널은 기존 기능을 모두 사용할 수 있도록 배치만 개편한다.

정렬·실행 취소·다시 실행 등 기존 상단 툴바 기능도 계속 제공한다. 상단 툴바를 제거하거나 해당 기능을 패널로 통합하려면 모든 기능의 대체 경로를 먼저 마련한다. 이미지의 글꼴명·크기값 때문에 기존 선택지를 줄이거나 임의의 새 값을 추가하지 않는다.

## 현재 구조에서 필요한 변경

- `RichBlock`에는 `alignment`와 `runs`만 있고 문단 들여쓰기 값이 없다. `htmlToBlocks`도 문단 정렬만 읽고 `blocksToHtml`도 정렬만 복원하므로 HTML에 여백을 넣는 것만으로는 저장되지 않는다.
- 문단 들여쓰기는 Run의 글자 서식과 분리하여 **문단 속성**으로 저장·전달한다. 구체적인 JSON 필드명과 단위는 구현 전에 계약에 반영한다.
- 현재 `PopupRichTextEditor`는 `contextmenu`를 가로채고 별도 `PopupRichTextMenu`를 연다. 이 경로를 유지하여 메뉴 내용을 펼침 팔레트 형태로 개편한다. 서식 적용은 기존 CKEditor 명령 경로를 재사용한다.
- 현재 커스텀 빌드의 문단 들여쓰기 플러그인 지원 여부는 확인이 필요하다. 우클릭 패널 개편을 위해 선택 툴바 플러그인이나 에디터 종류 변경을 선행 조건으로 두지 않는다.
- TODO28의 우클릭 메뉴 방향을 유지하며 UI 배치는 이 TODO49에서 구체화한다. 패널은 관리자 웹 편집 UI이고, WPF에는 기존 Run 서식과 새 문단 들여쓰기 값을 전달한다.

- 반복 들여쓰기: **단계 누적, 최대 5단계**. 문단 필드 `indent` = 0~5 정수(1단계 = 40px, 누락 = 0, 0이면 키 생략). 들여쓰기 늘리기·줄이기는 한 단계씩, 5단계에서 늘리기 비활성. `서식 지우기`는 글자 서식만 지우고 들여쓰기·정렬은 유지.
- CKEditor 빌드: 커스텀 빌드(v34)에 `Indent`·`IndentBlock`(offset 40px, `margin-left`)이 포함되어 있어 툴바에 `outdent`·`indent`를 추가해 사용. 최대 단계는 편집기 쪽에서 별도로 제한(아래 구현 결과).
- 색상: **명도 단계 격자로 확장** — 8계열(회색·빨강·주황·노랑·초록·청록·파랑·보라) × 밝기 5단계 = 40색, 기존 8색과 이름(검정·회색 등) 유지. 저장 규칙은 팔레트가 아니라 `#RRGGBB` 형식이므로 서버·WPF 계약 변경 없음. CKEditor 색 드롭다운도 같은 팔레트·8열.
- 패널 닫힘 규칙: **적용 후에도 열린 상태 유지**. Esc·바깥 클릭으로 닫고 편집기 선택으로 복귀.
