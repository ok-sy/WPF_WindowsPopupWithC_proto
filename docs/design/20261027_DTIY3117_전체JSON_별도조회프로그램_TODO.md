## 목적 · 보존 원칙

DTIY3117의 게시내용 CLOB에 팝업 전체 JSON을 저장하고, 이를 읽어 기존 WPF 단건 응답 형태로 반환하는 별도 Java 조회 프로그램을 추가한다.

- 기존 DTIY3111 조회 프로그램, Mapper/XML, PopupContentRow, PopupSingleResponseAssembler, 샘플 SQL, API 경로는 교체·삭제·수정하지 않는다.
- 신규 Controller·Service·Mapper/XML·조회 VO·JSON 응답 조립기를 별도로 둔다. 기존 클래스와 Bean 이름·매퍼 namespace·statement ID·URL 충돌을 방지한다.
- 별도 프로그램은 신규 Java 조회 기능을 뜻한다. WPF EXE 복제나 기존 WPF 응답 계약 변경은 범위에 포함하지 않는다.
- 최소 샘플이므로 HTTP 중계, 확장용 포트 인터페이스, 신규 오류 프레임워크, 전달 이력 저장 구조를 추가하지 않는다. 기존 인증·공통 오류 처리는 유지한다.

## 사진 스키마 근거

사진의 물리 컬럼명은 **POPU_BLTN_CN**으로 읽힌다. 대화에서 사용한 popup_bltn_cn과 다르므로 구현 전 실제 DB 정의를 확인한다. 아래는 사진 판독이며 확정 DDL이 아니다.

| 테이블 | 컬럼 | 사진 정의 | 용도 |
|---|---|---|---|
| DTIY3117 | POPU_ID | VARCHAR2(10), PK, NOT NULL | 팝업 ID |
| DTIY3117 | POPU_BLTN_CN | CLOB, NOT NULL | 팝업 게시내용 JSON |
| DTIY3117 | REG_USER_ID | VARCHAR2(6), NOT NULL | 등록 사용자 |
| DTIY3117 | REG_DTTM | DATE, NOT NULL | 등록 일시 |
| DTIY3117 | CHNG_USER_ID | VARCHAR2(6) | 변경 사용자 |
| DTIY3117 | CHNG_DTTM | DATE | 변경 일시 |

비고에는 JSON(content, plainText 포함), 일시에는 Sysdate가 보인다. Sysdate 비고만으로 DB DEFAULT 제약을 확정하지 않는다. 다른 테이블과의 외래키·대상자·게시기간 관계는 사진만으로 추정하지 않는다.

## 저장 JSON · 응답 경계

전체 JSON의 범위는 **popup 객체 본체**를 기준안으로 삼고, 실제 등록 화면 payload와 대조해 확정한다. `{pollingIntervalSeconds, popup}` 응답 envelope 전체를 저장하는 방식과 혼용하지 않는다.

```json
{
  "popupType": "TEXT",
  "title": "테스트 공지",
  "width": 560,
  "height": 420,
  "content": {
    "plainText": "테스트 팝업입니다.",
    "showPlainText": true
  },
  "questions": []
}
```

- content에는 유형별 본문·이미지/영상 URL·표시 옵션을 넣고 questions는 같은 저장 객체의 최상위 배열로 둔다. 3111용 임시 CNTN_CN.questions 추출 방식과 구분한다.
- popupId는 DB POPU_ID를 권위값으로 적용한다. 저장 JSON의 동일 필드가 불일치하면 덮어쓰기/거절 중 하나로 명시하고 테스트한다.
- deliveryId와 pollingIntervalSeconds는 게시내용으로 신뢰하지 않고 서버가 응답 시 설정한다. 입력 시 제거 또는 거절하는 기준을 정한다.
- 저장 내용은 관리자 편집 원본이며 조회 시 기본값 보정은 복사본에 수행한다. 조회만으로 저장 JSON을 갱신하지 않는다.
- 문항 원본에 정답 키가 포함될 수 있다. 기존 계약처럼 SURVEY 응답은 정답 키를 제거하고 QUIZ는 기존 채점 계약에 맞춰 처리한다. 전체 CLOB을 무검증으로 WPF에 전달하지 않는다.
