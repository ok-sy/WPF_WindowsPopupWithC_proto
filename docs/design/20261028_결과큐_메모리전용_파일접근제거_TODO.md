## 결정 · 범위

VMware 환경의 로컬 드라이브 쓰기 권한 제약 때문에 **결과 미전송 큐를 메모리에만 보관**한다. 정상 종료·강제 종료·프로세스 장애·재시작 때 서버가 수신하지 못한 결과가 사라지는 것은 수용한다. 이번 제공 경로에서 큐 파일 읽기·쓰기를 제거하는 결정이며, 단순 파일 저장 실패 fallback이나 파일 보관을 기본으로 둔 선택 옵션 도입 계획이 아니다.

이번 범위는 결과 큐뿐이다. 로그·WebView2 캐시·기타 파일 사용은 변경하지 않고 실제 운영 환경 테스트에서 별도 확인한다. 이 작업으로 프로그램 전체가 무디스크 실행 가능하다고 주장하지 않는다.

## 현재 코드에서 주의할 점

기준 파일: `popup-frameWork/Popup/Services/PopupResultQueue.cs`.

- 현재 큐는 LoadPendingUnlocked/SavePendingUnlocked/TrySavePendingUnlocked에서 파일을 사용하며 _unsaved는 디스크 실패 보관분이다.
- 파일 함수를 단순 no-op 처리하면 Enqueue의 지역 목록만 변경되고 결과가 실제 큐에 남지 않을 수 있다. 영속 목록을 단일 메모리 목록으로 대체하는 작업이 먼저 필요하다.
- 시작 시 복원뿐 아니라 PendingCount·Enqueue·Flush·종결 후 제거·RetainForExit에도 디스크 경로가 있다. 전 경로를 확인한다.
- 현재 fileAvailable 기반 Blocked 처리와 파일 저장 실패 UI는 영속화 장애를 전제로 한다. 디스크 부재 때문에 전송이 차단되지 않도록 바꾸되 업무 오류/인증/버전 차단 의미는 유지한다.

- [ ] **파일 접근 전부 제거**: File.Exists/ReadAllText/WriteAllText/Move/Delete, Directory.CreateDirectory, 임시/손상 백업 파일, 큐 경로/LocalApplicationData 계산·이관·복원 경로를 제거한다. 생성자·건수 조회·실패 처리에서도 파일을 탐색하지 않는다.
- [ ] **전송 유지**: 실행 중 Flush·재시도·순서·중복 resultId 처리·원본 resultId/deliveryId 유지. 같은 항목 재시도 시 식별자를 다시 만들지 않는다.
- [ ] **종결 유지**: 응답 resultId가 요청과 같고 ACCEPTED/DUPLICATE/REJECTED일 때만 해당 항목을 제거한다. 통신 실패·재시도 오류를 전송 성공처럼 버리지 않는다. 잘못된 resultId는 큐에 남긴다.
- [ ] **기존 오류 정책 유지**: 400 격리, 세션 내 INTERNAL_ERROR 제한, 426 전송 중단 및 기존 인증 처리의 의미를 유지한다. 격리·재시도 제한 항목도 실행 중에는 보관하며 이 작업을 근거로 별도 정책 전체를 변경하지 않는다.
- [ ] **동시성**: Flush 중 새 Enqueue·같은 resultId 갱신·종결 제거 경쟁을 점검한다. 네트워크 전송은 잠금 안에서 기다리지 않고 기존 전송 직렬화 보장을 유지한다. 새 항목/갱신 항목을 과거 응답으로 잘못 제거하지 않는다.
- [ ] **종료 처리**: StopTransmission과 RetainForExit는 파일 저장 없이 동작한다. 종료 직전 무리한 동기 전송·새 파일 flush를 추가하지 않는다. 미전송 결과는 프로세스 종료와 함께 사라진다.
- [ ] **일반/API Demo 연결**: 모든 PopupResultQueue 생성 지점을 수정한다. 연결 대상·인증 사용자별 큐 분리를 유지하고 다른 서버/사용자의 미전송 결과를 전송하지 않는다. 파일 해시/경로 대신 메모리 수명·연결 전환 처리를 명시한다.
- [ ] **UI·오류 정리**: 파일 저장 실패 때문에 닫기/제출이 막히는 안내·건수 조회 오류·종료 복구 안내를 메모리 정책에 맞춘다. 실제 HTTP 실패 안내와 서버 미수신 표시를 제거하지 않는다.
- [ ] **기존 파일**: 남아 있는 pending-results.json을 자동으로 읽거나 수정·삭제·이관하지 않는다. 기존 파일을 정리하는 별도 작업은 이번 범위 밖이다.
