## 목적과 범위

현재 VIDEO+QUIZ는 VideoQuizPopupView 전체 영상 행 높이를 300 DIP로 고정해 제목·설명이 실제 재생 공간을 차지한다. 관리자 웹 미리보기와 WPF 영상 결합 QUIZ에서 실제 재생 영역의 가용 너비와 원본 영상 종횡비로 높이를 계산하도록 변경한다.
대화의 “video+popup”은 직전 논의한 VIDEO+QUIZ 결합 팝업으로 해석한다. 단독 VIDEO 크기 정책은 이번 필수 변경 범위에서 제외하고 공유 컴포넌트 회귀만 확인한다.

## 합의된 기본 방향
- React의 HTML video와 WPF WebView2의 HTML video가 메타데이터를 읽어 제공하는 videoWidth/videoHeight를 사용한다.
- 브라우저가 제공하는 표시용 고유 크기를 기준으로 비율을 계산한다. 서버에 파일 분석 라이브러리나 ffprobe를 추가하지 않는다.
- 실제 재생 영역 너비 W와 유효한 영상 크기 w/h에 대해 목표 높이 H = W × h / w로 계산한다.
- W는 팝업 전체 width가 아니라 내부 여백·테두리·스크롤바 등을 제외한 실제 플레이어 가용 너비다.
- 제목·설명·별도 컨트롤이 차지하는 높이는 재생 화면 밖에서 추가한다. overlay 형태의 컨트롤 높이는 중복 가산하지 않는다.
- 영상과 퀴즈는 기존 부모 세로 스크롤을 공유하고 제출 영역은 기존 고정 위치를 유지한다.
- Description 공통화는 보류 상태를 유지한다. TODO59의 중간 notice 제거와 충돌하지 않게 한다.

### WPF
- 60-1·4: VideoQuizPopupView의 고정 300 행(제목·설명 포함)을 Auto로 바꾸고, VideoPopupView의 재생 행(`VideoRow`)만 원본 비율 높이로 계산한다(`VideoPopupView.AspectSizing.cs`). 제목·설명은 기존 Auto 행이라 영상 외 영역은 한 번만 합산된다. 컨트롤바는 영상 위 오버레이라 높이에 더하지 않는다. 단독 VIDEO는 EnableAspectSizing을 부르지 않아 기존 `*` 행 그대로다.
- 60-2·3: WebView2 HTML에 `resize` 이벤트를 추가하고 모든 메시지에 `videoWidth/videoHeight`와 문서 로드 ID(`loadId`)를 싣는다. 로드 ID가 다른 메시지는 무시한다. `resize` 메시지는 크기만 반영하고 재생 상태·시청량 계산 전에 반환한다. MediaElement는 MediaOpened의 NaturalVideoWidth/Height를 쓴다. 양수·유한값만 받고 같은 크기는 다시 적용하지 않는다.
- 60-5: 영상 레이아웃 너비 변화·부모 스크롤 높이 변화·원본 크기 수신 때 다시 계산한다. 0.5 미만 변화는 무시하고, 높이 변경 → 스크롤바 표시/숨김 → 같은 두 너비를 오가는 경우 마지막 높이를 유지해 진동을 막는다. 전체화면 중에는 계산하지 않고 복귀 시 다시 계산한다.
- 60-9: 크기 갱신은 재생·위치·시청량 경로를 거치지 않는다(테스트로 LatestProgress 불변 확인). 회전 메타데이터는 각 엔진이 보고하는 표시 크기를 그대로 쓴다(별도 회전 처리 없음).

### 관리자 웹 미리보기(60-6)
- 미리보기는 영상을 재생하지 않던 자리표시자였다. VIDEO+QUIZ만 `AspectVideoArea`로 바꿔 `<video preload="metadata" muted>`의 loadedmetadata·resize에서 크기를 읽고, ResizeObserver로 실제 너비·가장 가까운 세로 스크롤 영역 높이를 측정해 WPF와 같은 식을 적용한다. URL이 바뀌면 이전 비율을 버리고, 언마운트 시 관찰자를 해제한다. 영상 URL은 텍스트 입력만 있어 object URL 경로는 없다.
