## 목적과 범위

현재 VIDEO+QUIZ는 VideoQuizPopupView 전체 영상 행 높이를 300 DIP로 고정해 제목·설명이 실제 재생 공간을 차지한다. 관리자 웹 미리보기와 WPF 영상 결합 QUIZ에서 실제 재생 영역의 가용 너비와 원본 영상 종횡비로 높이를 계산하도록 변경한다.
대화의 “video+popup”은 직전 논의한 VIDEO+QUIZ 결합 팝업으로 해석한다. 단독 VIDEO 크기 정책은 이번 필수 변경 범위에서 제외하고 공유 컴포넌트 회귀만 확인한다.

## 합의된 기본 방향
- React의 HTML video와 WPF WebView2의 HTML video가 메타데이터를 읽어 제공하는 videoWidth/videoHeight를 사용한다.
- 브라우저가 제공하는 표시용 고유 크기를 기준으로 비율을 계산한다. 서버에 파일 분석 라이브러리나 ffprobe를 추가하지 않는다.
- 실제 재생 영역 너비 W와 유효한 영상 크기 w/h에 대해 목표 높이 H = W × h / w로 계산한다.
- W는 팝업 전체 width가 아니라 내부 여백·테두리·스크롤바 등을 제외한 실제 플레이어 가용 너비다.
- 제목·설명·별도 컨트롤이 차지하는 높이는 재생 화면 밖에서 추가한다. overlay 형태의 컨트롤 높이는 중복 가산하지 않는다.
- 영상과 퀴즈는 기존 부모 세로 스크롤을 공유하고 제출 영역은 기존 고정 위치를 유지한다.
- Description 공통화는 보류 상태를 유지한다. TODO59의 중간 notice 제거와 충돌하지 않게 한다.

## 구현 시 구체화할 표시 정책
아래 수치 정책은 아직 확정하지 않았으며 구현 전 화면 비교로 정하고 문서에 기록한다.
- 메타데이터 로드 전 임시 비율: 16:9를 우선 검토한다.
- 세로/극단 비율 영상의 최대 재생 영역 높이: 팝업 가용 높이에 대한 비율 또는 제한값을 검토한다. 특정 숫자를 이번 TODO에서 확정하지 않는다.
- 최대 높이를 적용하면 영역은 제한하되 영상은 contain 방식으로 원본 비율을 유지해 표시한다. 영상 잘림·왜곡은 허용하지 않는다.
- 읽기 실패/크기 0/비정상 값은 마지막 유효 크기 또는 기본 비율로 안전하게 표시한다. 다른 영상으로 바뀌면 이전 영상의 비율을 재사용하지 않는다.
- 관리자 미리보기와 WPF는 같은 계산·제한 원칙을 사용한다. CSS px와 WPF DIP, DPI에 따른 실제 물리 픽셀까지 같다고 단정하지 않는다.
