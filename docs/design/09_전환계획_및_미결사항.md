## 1. 구현 순서

**진행 상태 (2026-09-19)**: 단계 1(Oracle 21c XE `XEPDB1`에 `db/oracle/00~03` 적용)·2·3·4·5·6 완료, 단계 7은 베이스라인에서 이미 충족. 서버 매퍼와 신규 WPF API는 **실DB 롤백 테스트로 검증**(`PopupQuestionDatabaseTest`, `WpfPopupDatabaseTest`). **WPF↔서버 HTTP 실연동 완료**(팝업 슬라이스 개발 서버 `:app:wpfDevServer` + Oracle: 목록 조회 → 팝업 표시 → 닫기 → 결과 API → USER_POPUP_STATUS/영수증/로그 기록 확인, `WpfApiOracleHttpTest` 4건). 미수행: 단계 0의 SSO/통합 토큰 확정, **전체 zeroserver 기동**(공통 프레임워크 clover-* POSTGRE 빌드·공통 매퍼 13개가 PostgreSQL 전용 — 미결 15), 단계 8.

**진행 상태 (2026-09-20)**: 서버 공통 베이스라인을 업스트림 `zero-rule-server` @`56bb0c5`(Oracle, cloverframework `3.0.3-SNAPSHOT`)로 교체하고 popup·WPF 소스 71개와 추가형 설정을 재적용(커밋 `0294d1e` = 업스트림 원본). **전체 zeroserver가 Oracle에서 기동**(로컬 XE, `ZERO_RULE_DB_*` 환경변수)하며 공통 `CustomAuthenticationFilter`를 거친 `/p/api/wpf/popups` 401/200·결과 ACCEPTED/DUPLICATE 확인 → 미결 15 해소. 발견·수정: `custom.wpf-popup.dev-user-header`를 common과 local 양쪽에 두면 프로파일 활성 순서(local → common)상 common 값이 이겨 로컬 개발 헤더가 꺼짐 → common에서 제거. 새 미결 16(nav 기능), 17(로컬 공통 스키마 `CLOVER_BATCH_NODE` PK 충돌).

**진행 상태 (2026-09-20, 2차 — 원격 DB)**: 원격 개발 DB는 **Oracle 11g XE 11.2.0.2**(설계 가정 19c와 다름). DDL을 11g 호환으로 수정(제약명 30자, `IS JSON` 제거)하고, 앱 계정 `zero-rule`에 CREATE USER 권한이 없어 팝업 테이블을 그 계정 스키마에 생성. 매퍼의 `POPUP.` 한정자를 설정 `custom.popup.schema`(`${popupSchemaPrefix}`)로 빼서 로컬(POPUP 계정)·원격(앱 계정 스키마) 양쪽 지원. 원격으로 실DB·HTTP 테스트 통과, **WPF exe ↔ 전체 서버 ↔ 원격 DB 왕복 확인**. 미결 1·15·16·17 해소.

**진행 상태 (2026-09-21 — SSO·토큰 프로토타입, 설계 10)**: WPF가 사내 SSO(Windows 통합 인증)에서 얻은 사용자 정보로 `POST /p/api/wpf/auth/login`을 호출해 10분 유효 opaque 토큰을 메모리에 보관하고 `Authorization: Bearer`로 WPF API를 호출하는 흐름을 구현·검증했다. 서버는 `custom.wpf-auth-prototype.enabled=true`(로컬 프로파일)일 때만 로그인 API와 토큰 검사(`PrototypeTokenWpfUserResolver`, `@Primary`)를 켠다. 검증(로컬 XE + 임시 SSO 프로그램 `popup-frameWork/MockSso`(Negotiate 도전), TTL 20초로 단축): T1 최초 실행 SSO→로그인→팝업 GET 200, T2/T3 만료 후 결과 POST 401 → SSO·재로그인 → **같은 resultId로 1회 재전송 → 영수증 1건 ACCEPTED**, T4 정기 재로그인(1분으로 단축) 401 없이 재발급, 구 이벤트/영상 진행률 API 호출 없음. 임시 SSO의 Negotiate 도전에 WPF `UseDefaultCredentials`가 NTLM으로 응답해 XML을 받는 것까지 확인(관리 화면 "SSO 로그인 테스트" 버튼). 미실행: T5 동시 401(코드 설계로만 보장), T6·T7, 실제 사내 SSO URL 연결. 상세는 [04 §6](04_인증설계.md)·[10](10_WPF_SSO_토큰_프로토타입_계획.md).

## 3. 데이터 이관 (PostgreSQL → Oracle)

운영 데이터가 PostgreSQL에 있다면 다음 순서로 이관한다. 개발 샘플만 있다면 이관하지 않는다.

1. 조직 마스터 → 템플릿 → 문항 → 선택지 → 팝업 → 콘텐츠 → 대상 → 상태 → 응답 → 영상 → 로그 순 (FK 순서).
2. IDENTITY 값은 그대로 삽입하고, 이관 후 각 시퀀스를 `MAX(id)+1`로 재설정.
3. `content_options` JSONB → 텍스트 그대로 CLOB (IS JSON 통과 확인).
4. `TIMESTAMP` 값은 원본이 KST 로컬 시각이므로 변환 없이 이관. `AT TIME ZONE` 후처리 불필요.
5. 이관 후 `03_validation.sql`(참조 저장소)을 Oracle 문법으로 옮겨 건수·대상 계산 결과를 대조.

## 5. 위험과 완화

| 위험 | 완화 |
|---|---|
| 기존 `PopupMapper.xml` Oracle 변환 중 의미 변경 | 구문별 변환표(05 §5) 기준으로 1:1 대조. 관리자 화면 왕복 테스트 |
| 타 팀 통합 토큰 필터가 `/p/api/wpf/**`에 적용되기 전까지 사용자 식별 공백 | 개발 프로파일에서만 `X-Dev-User-Id` 허용. 운영 프로파일은 `dev-user-header=false` 고정, 필터 적용 전 운영 배포 금지 |
| 결과 전송 유실로 완료 상태 누락 | 로컬 큐 + 멱등 키 + 시작 시 flush |
| 팝업 열림 중 주기 조회로 중복 표시 | `HasOpenPopups`면 조회 건너뜀 |
| Oracle `IN` 절 1000개 제한 | 템플릿·문항 ID 수가 소규모. 초과 시 분할 조회 |
