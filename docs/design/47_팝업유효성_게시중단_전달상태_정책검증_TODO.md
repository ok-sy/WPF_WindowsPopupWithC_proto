## 결정 (2026-10-13)

- 47-4: 이미 열린 팝업의 강제 회수와 긴급 공지 끼어들기는 **범위 밖으로 확정**한다. 게시중단 전에 표시된 팝업의 결과는 현행대로 수용한다(만료된 EXPIRED 전달 건 포함). (2026-10-15 보완: 당시 구현은 활성 해제 방식의 게시중단에서 CLOSED·HIDDEN을, 활성 해제·기간 종료·대상 변경에서 SUBMITTED·VIDEO_WATCHED를 거절하고 있었음 — 47-4 확인은 기간 종료 CLOSED 경로만 통과. 설계 50 A9에서 결과 수용 조건을 신규 조회 게시 조건과 분리해 수정.)
- 47-5: 진행 단위는 **사번 단위 유지**(사용자당 OPEN 전달 건 1건, 잠금 순서 사용자 → 전달 건). 한 PC에서 완료하면 이후 다른 PC의 조회에서도 제외한다. **보류**: 여러 PC의 동시 표시 허용 여부, 이미 다른 PC에 열린 팝업의 결과 수신 기준(현재 동작: 같은 사번의 두 PC는 같은 OPEN 전달 건을 받고, 먼저 저장한 결과가 반영되며 다른 PC의 다른 resultId 결과는 WPF_DELIVERY_COMPLETED로 거절·종결).
- 47-7: resultId 본문 비교·보존 기간·전달 건 만료(시간 기준)는 TODO45와 같이 **주간회의까지 보류**. 현재: 본문 비교 없음, 보존 기간 없음, 전달 건은 재조회 시 대상이 아니면 EXPIRED, 시간 만료 없음. 동률 정렬 DISPLAY_ORDER → CREATED_AT → POPUP_ID, 유예가 끝난 팝업은 같은 정렬로 다시 후보가 된다.
