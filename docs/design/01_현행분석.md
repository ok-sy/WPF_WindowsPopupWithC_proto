## 2. 현행 WPF ↔ 서버 인터페이스 (12개 중 WPF 6개)

| ID | HTTP | 경로 | 호출 시점 (현행 WPF) | 문제점 (기준 항목) |
|---|---|---|---|---|
| WPF-01 | GET | `/p/api/popups?userId=` | 시작 + `PollingIntervalSeconds`(300초) 주기 | userId를 쿼리로 전달 (6). 완료 여부 판단이 서버에 없음 (2) |
| WPF-06 | GET | `/p/api/popups/statuses?userId=` | WPF-01 직후 매번 | 완료 팝업 제외를 WPF가 수행 (2). 별도 API (3) |
| WPF-05 | POST | `/p/api/popups/{id}/events` | 팝업 `ContentRendered`(DISPLAYED), `Closed`(CLOSED) 마다 | 팝업 1개당 2회 실시간 호출 (4) |
| WPF-04 | POST | `/p/api/popups/{id}/video-progress` | `_progressSaveTimer` 주기 + pause/seek/종료 | 영상 1개당 다수 실시간 호출 (4) |
| WPF-02 | POST | `/p/api/popups/{id}/hide` | "다시 보지 않기" 클릭 | 결과 API 분산 (3), 본문 userId (6) |
| WPF-03 | POST | `/p/api/popups/{id}/responses` | 설문/퀴즈 제출 | 결과 API 분산 (3), 본문 userId (6) |

## 3. 노출 대상 판단의 현행 분담

| 판단 항목 | 서버 (`selectAvailablePopups`) | WPF |
|---|---|---|
| 활성 여부 `active_yn` | O | – |
| 노출 기간 `display_start_at ~ display_end_at` | O | `PopupPolicyService.CanShow`에서 **중복 검사** |
| 대상 조건 (그룹 OR / 조건 AND, 부서 하위 포함) | O (재귀 CTE + `BOOL_AND`) | – |
| 숨김 `hidden_until_at > now` | O | `PopupStorageService.IsHidden`으로 **로컬 파일 중복 판단** |
| 완료 여부 `completed_yn` | **X** | `/statuses` 조회 후 `completed`인 팝업 제외 |
| 문항 템플릿 활성 | O | – |

→ 기준 2에 따라 완료 여부까지 서버 SQL에 포함하고, WPF의 `PopupPolicyService`·`PopupStorageService`(숨김 로컬 저장)를 제거한다.

## 4. 응답 JSON 구조의 현행 문제

- 설문/퀴즈 문항이 최상위 `questions`와 `content.questions`에 **중복** 제공된다 (`PopupService.toResponseDto`). WPF는 `content.questions`를 읽는다 (`PopupFactory` → `SurveyPopupContentDto.Questions`).
- `content`는 매퍼에서 `JSONB_BUILD_OBJECT(...) || content_options`로 조립한다. Oracle 전환 시 그대로 옮기기 어렵다 (기준 5).
- `passingScore`, `questionTemplateId`가 사용자 응답에 노출된다. 채점은 서버가 하므로 WPF에 불필요하다.
- 날짜는 `WRITE_DATES_AS_TIMESTAMPS`로 epoch 초(소수 가능)로 나간다. WPF는 `FlexibleDateTimeOffsetJsonConverter`로 ISO/epoch 모두 처리한다.

## 5. 인증 현행

- `/p/**`는 `DefaultPublicUrls`로 `permitAll`이며 `CustomAuthenticationFilter.processJwt`는 `/p/` 경로에서 토큰이 없어도 통과시킨다.
- 관리자 웹 로그인은 `POST /p/api/auth/login` (lgonId/passwd) → `zero_rule.clover_user_auth`에 토큰 저장, `x-custom-authorization` 헤더 사용.
- WPF는 `appsettings.json`의 `UserId`(예: `E1002`)를 그대로 쿼리/본문에 보낸다. **누구든 임의의 userId로 조회·제출 가능**하다.
- 저장소 `STRUCTURE_REVIEW.md` P2 "공개 API 사용자 식별"에서 이미 위험을 인지하고 있다.

## 6. DB 현행 (PostgreSQL `popup` 스키마 16개 테이블)

| 구분 | 테이블 |
|---|---|
| 조직 마스터 | `app_department`, `app_position`, `app_user` |
| 팝업 정의 | `popup_notice`, `popup_content`, `popup_target_group`, `popup_target_condition` |
| 문항 | `question_template`, `popup_question`, `popup_option` |
| 사용자 상태·결과 | `user_popup_status`, `popup_response`, `popup_response_answer`, `popup_response_value`, `video_view_status` |
| 로그 | `api_request_log` (현재 Java는 `zero_rule.clover_api_log` 사용, 미사용 테이블) |

PostgreSQL 전용 요소 (Oracle 변환 대상):

| 요소 | 사용 위치 |
|---|---|
| `BIGINT GENERATED BY DEFAULT AS IDENTITY` | 모든 대리키 테이블 |
| `JSONB`, `JSONB_BUILD_OBJECT`, `\|\|` 병합, `::JSONB` | `popup_content.content_options`, 매퍼 content 조립 |
| `TEXT` | `content_body`, `correct_answer`, `text_answer`, 로그 컬럼 |
| `CREATE UNIQUE INDEX ... WHERE current_yn = 'Y'` (부분 인덱스) | `question_template` |
| `num_nonnulls()` | `popup_target_condition` CHECK |
| `CASE ... ELSE FALSE` (boolean 결과), `BOOL_AND()` | 매퍼 `selectAvailablePopups`, DDL CHECK |
| `WITH RECURSIVE` | 부서 트리 |
| `INSERT ... ON CONFLICT DO UPDATE`, `EXCLUDED`, `RETURNING` | 모든 upsert·insert |
| `CURRENT_TIMESTAMP + (n * INTERVAL '1 day')` | 숨김 만료 |
| `AT TIME ZONE 'Asia/Seoul'` | 모든 날짜 SELECT |
| `gen_random_uuid()::text` | 템플릿 그룹 ID |
| `SET LOCAL search_path` | DDL |
