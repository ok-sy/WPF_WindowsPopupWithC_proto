# 폐쇄망 FRONT 단계별 반영 체크리스트

작성: 2026-10-30 (KST) / 기준: GitHub main 소스 정적 확인
상태: **반입 계획 문서만 작성. 폐쇄망 반영·빌드·실화면 검증 미실행.**
대상: 기존 폐쇄망 `zero-rule-web`에 단계적으로 변경분 반영

## 반영 순서 한눈에 보기

| 순서 | 묶음 | 반영 결과 / 다음 단계 조건 |
|---|---|---|
| 0 | 반입 준비 | 기존 소스 백업, HEAD·lockfile·의존 패키지 확보 |
| 1 | FRONT / Turbopack | 기존 화면이 `pnpm dev`로 실행되고 SVG 로딩 정상 |
| 2 | MUI Icon | 메뉴·아이콘 선택 화면 표시 정상, 전체 아이콘 일괄 import 제거 |
| 3 | CKEditor | 게시판·자료실 Common/Bbs 편집기 정상, 단일 CKEditor 엔진 설치 |
| 4 | PopupcommonComponent | 본문·문항·일정·미리보기·필드 추출 재사용 확인 |
| 5 | 화면 연결·최종 검증 | RgstPop/IS063M02Sample/Guide 등 필요한 화면 연결, 빌드·로그인 확인 |

**중요:** 각 단계는 **소스 반영/검증 순서**다. npm 의존성은 `pnpm-lock.yaml` 기준으로 한 번에 설치하는 것이 원칙이다. Turbopack은 개발 서버(`next dev --turbopack`)이고 운영 `next build`는 현재 webpack 설정을 사용한다.

## 0. 반입 전 준비 (필수)
- [ ] 폐쇄망 기존 `zero-rule-web` 및 로컬 수정분 별도 백업. 외부망 소스 HEAD, 기존 폐쇄망 기준 커밋, 패키지 파일의 차이를 기록.
- [ ] `scripts/export-offline-package.ps1`에서 만든 `2-zero-rule-web.tar`, `MANIFEST-2-zero-rule-web.txt`, 삭제 목록/충돌 목록 검토. **A=신규, M=기존 파일 수정, D=삭제** 구분. 반입본은 커밋된 HEAD 기준(미커밋 파일 제외).
- [ ] `zero-rule-web/package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `main/package.json`, 필요한 `sub/*` workspace 의존 파일을 함께 비교·반영. 이전 폐쇄망 소스에 있는 업무용 변경을 무조건 덮어쓰지 않음.
- [ ] Node.js 설치 및 `pnpm --version` **9.15.2** 확인(`zero-rule-web/package.json`의 packageManager). `pnpm store path`와 오프라인 패키지 보유 여부 확인.
- [ ] `@svgr/webpack`, `svg-url-loader`, Next, MUI, CKEditor를 포함한 **전체 lockfile 의존성**이 폐쇄망 pnpm store에 있는지 확인. 기존 store에 없으면 인터넷 연결 PC에서 해당 lockfile 기준 추가 묶음 제작. CKEditor 전용 묶음만으로 전체 프로젝트에 필요한 모든 npm 패키지가 제공되는 것은 아님.
- [ ] CKEditor 전용 오프라인 캐시: 인터넷 연결 PC에서 `node scripts/prepare-offline-npm.cjs` 출력물 `pnpm-store-v3.tgz`·`PACKAGES.txt`·`install-pnpm-store.ps1`·`README-NPM.md` 확보. 필요 시 `export-offline-package.ps1 -NpmBundleDir .offline-cache/npm-ckeditor/bundle`로 통합.
- [ ] `2-zero-rule-web.tar`의 package/lockfile을 먼저 반영한 뒤 pnpm store를 채우고 **프로젝트 루트(`zero-rule-web`)**에서 `pnpm install --offline --frozen-lockfile`. `ERR_PNPM_NO_OFFLINE_TARBALL` 발생 시 오류에 나온 패키지를 별도 확보하고 반복. 임의 버전 변경 금지.

## 1. FRONT / Turbopack
**주요 파일**
- `zero-rule-web/main/package.json` — `dev: next dev --turbopack`, `dev:webpack: next dev`, `build: next build`.
- `zero-rule-web/main/next.config.mjs` — `turbopack.rules['*.svg']`의 `@svgr/webpack` 이름 내보내기; 기존 `webpack` SVG 설정은 운영 빌드용으로 유지. `transpilePackages`에 `sub/*/package.json` 이름(`@local/*`·`@repo/*` 등)을 자동 추가. **폐쇄망 next.config.mjs에 다른 설정(webpack alias 등)이 있으면 덮지 말고 병합.**
- `zero-rule-web/main/src/components/NotReady/NotReady.tsx` — SVG를 `public/images/under_construction1.svg` 주소로 사용. **반드시 함께 반영**: 빠지면 Turbopack에서 `Export default doesn't exist in target module`(SVG default import는 Turbopack 규칙에서 제공하지 않음). 폐쇄망 자체 코드에 `import x from '*.svg'`(default)가 있으면 같은 방식으로 public 경로 문자열로 바꾼다.
- `shell/start-dev.ps1` — 개발 서버 기동 시 기존 스크립트를 쓰는 경우 주석/환경변수 전달 확인.

**적용/검증**
- [ ] 위 파일을 폐쇄망 소스와 비교·반영; `public/images/under_construction1.svg` 실파일 존재 확인.
- [ ] `cd zero-rule-web/main` 후 `pnpm dev` 실행. 기존 로그인/사이드바, SVG 사용하는 화면 정상 확인.
- [ ] 문제가 있으면 `pnpm run dev:webpack`으로 비교. **Turbopack 설정을 운영 webpack에 덮어쓰지 않는다.**
- [ ] `next.config.mjs`의 환경변수(BASE_URL/ROUTER_BASE_URL/API_BASE_URL)와 폐쇄망 값 확인.

## 2. MUI Icon 로딩 최적화
**주요 파일**
- `zero-rule-web/main/src/components/StringToMuiIcon/MuiGenericIcon.tsx` — `import * as icons` 실행 import 대신 실제 아이콘을 **개별 경로**로 import하고 `MENU_ICONS` 맵 사용.
- `zero-rule-web/main/src/components/StringToMuiIcon/StringToMuiIcon.tsx` — 현재 호출 계약 보존(변경 필요 시 차이 확인).
- `zero-rule-web/main/src/components/IconSelectPaper/icon-collection.tsx` — 선택 가능한 아이콘 목록(`DEFAULT_ICON_LIST`).
- 의존 패키지: `@mui/material`, `@mui/icons-material`, `@emotion/react`, `@emotion/styled`(버전은 폐쇄망 반영 lockfile 기준).

**적용/검증**
- [ ] `MuiGenericIcon.tsx` 및 연결 파일을 비교·반영하고 전체 네임스페이스 **실행 import**가 남지 않았는지 확인(`import type *`은 타입 선언이므로 별도).
- [ ] **사전 확인 필요:** 현재 main의 `DEFAULT_ICON_LIST` 37개 중 `MENU_ICONS`에 없는 이름 7개(`LightbulbCircle`, `Phone`, `PowerSettingsNew`, `QuestionMark`, `Search`, `Telegram`, `ThumbUp`). 메뉴/선택기에서 이 이름을 사용할 계획이면 맵 추가 후 반입; 선택 목록과 표시 맵이 항상 일치하도록 검증.
- [ ] 사이드바 아이콘·아이콘 선택 창·선택 후 표시·기존 DB 등록 아이콘 확인. 등록되지 않은 이름은 현재 빈칸으로 표시됨을 인지.
- [ ] 캐시 없는 첫 진입 컴파일·페이지 이동 속도 비교(가능하면 이전과 소요시간 기록).

- `zero-rule-web/main/src/components/ckeditor/index.ts`, `ckeditorEngine.ts`: 유일한 엔진·플러그인 출처, `next/dynamic(ssr:false)`, `ckeditor5/ckeditor5.css`, 한국어 UI.

- [ ] 개발자 콘솔에서 `ckeditor-duplicated-modules`, `toolbarview-item-unavailable`, 편집 불가 오류가 없는지 확인.
- [ ] 4단계 반입 후 **자료실→팝업 등록→자료실**, 반대 순서 이동까지 다시 확인.

## 명령어 예시 (폐쇄망 PowerShell)

```powershell
cd D:\경로\zero-rule-web
node -v
pnpm -v                         # 9.15.2 권장(프로젝트 지정 버전)
pnpm store path
# CKEditor 묶음 폴더에서 .\install-pnpm-store.ps1 -WebRoot D:\경로\zero-rule-web
pnpm install --offline --frozen-lockfile

cd .\main
pnpm list ckeditor5 @ckeditor/ckeditor5-react --depth 0
pnpm dev                        # Turbopack 개발 서버
# 비교 필요 시: pnpm run dev:webpack
pnpm type-check
pnpm build                      # 현재 webpack 운영 빌드
```
