### 확인된 차이·결정 필요 (B 후보 최초 기록, 이후 결정은 §4-2 참조; 코드 미수정)

1. 서버 채점 신뢰: 클라이언트 `passed`를 그대로 저장하고 `passed == (score >= passingScore)` 일관성도 보지 않음. 서버 판정 기준으로 바꿀지 결정 필요.
2. Q3 연결: passingScore 미설정(null·0 이하)이면 WPF·서버 모두 항상 통과. 운영 저장은 null을 거부하지만 3117·3111 샘플 경로는 QUIZ passingScore null이 남을 수 있음.
3. QUIZ 불합격 뒤 '보지 않기' 체크 + 보조 닫기/Alt+F4로 나가면 통과 없이 HIDDEN 기록 가능.
4. 서버 제출 검증에 SURVEY 최소·최대 선택 수 검사 없음(WPF·웹만 막음).
5. 서버는 LATER 수신 시 팝업 `showLater` 설정을 확인하지 않음(인터페이스 명세에 기록된 의도).
6. VIDEO+QUIZ 재생 실패 시 퀴즈 진행 불가·닫기만 허용이 Q1 "재생 오류 기존 예외" 범위인지 확인.
7. 웹 미리보기 fallback 0.8(독립 샘플·가이드) ↔ 실제 1.0.
8. `docs/interfaces/WPF_POPUP_MINIMAL_SPEC.md`: ShowLater 행 없음, 128행 "QuestionScore 누락이면 0점"은 코드·ALL_SPEC(1점)과 다름(2026-11-03 MINIMAL_SPEC을 1점 기준으로 정정, 결과 `score`·`passed` 전달 설명·ShowLater 행도 추가), 132행 TEXT 자동 채점 제외는 최초 범위 정의라 유지 여부 확인. 최소 범위 계약 문서라 임의 수정하지 않음.

### Q3 QUIZ 3유형 기획서 확인 및 결과 UI 최종 결정 (2026-11-03, 기획서 106/109)

> 기획서 이미지의 **4 커트라인형 / 5 만점형 / 6 참여형** 결과 화면을 대조했다. **참여형의 기존 '점수·안내 미표시 후 즉시 종료' 결정은 철회하고, 이번에 사용자가 승인한 '정답 개수 + 완료 안내 + 확인 후 종료'로 대체한다.** 이는 정책·TODO 결정 기록이며 코드 구현 완료를 뜻하지 않는다.

**기획서 표현 주의**
- 결과 화면의 `7/10개`, `3/10개`, `2/10개`는 **점수 숫자 자체가 아니라 정답 개수/전체 문항 개수 표기**다. 현재 문항별 배점이 모두 1점인 경우에는 실제 `score`와 정답 개수가 같지만, 배점 변경 가능성을 고려해 의미를 구분한다.
- **커트라인형 성공**: 기획서에는 "퀴즈를 통과하여 보안 퀴즈를 종료합니다."와 정답 개수/확인 버튼을 표시한다. **실패**: "퀴즈를 통과하지 못하였습니다. 문제를 다시 풀어주세요. (통과 기준: 6개 이상)"과 정답 개수/다시 풀기를 표시한다.
- **만점형 성공**은 확인 버튼, **실패**는 다시 풀기 버튼이다. 성공·실패 예시에 정답 개수 표시는 보이지 않으므로 **기획서 기준 필수로 단정하지 않는다**.
- **참여형**은 사용자 확정에 따라 정답 개수 `2/10개` 및 완료 안내를 표시하고 사용자가 **확인**을 누른 뒤 팝업을 종료한다. 이전에 정한 무안내 즉시 종료는 적용하지 않는다.

**기존 계약 활용과 구분**
- 신규 `popupType`, `quizMode`, `passYn` 등 JSON 필드를 추가하지 않는다. WPF가 로컬 채점 후 실제 점수를 `score`로, 통과/완료 판정을 `passed`로 WPF-02 `SUBMITTED` 요청에 포함한다. 참여형 `passed=true`는 만점이 아니라 '참여 제출 완료'를 의미한다.
- 1점/문항이면 `passingScore=6`은 6/10 이상, `passingScore=10`은 10/10 만점, `passingScore=0`은 참여형에 대응한다. 배점이 달라지면 **passingScore는 점수**, 화면의 `N/M개`는 **정답 문항 개수**이므로 별도 산출 기준을 확인한다.
- 기존 WPF는 통과할 경우 결과 안내 모달을 표시한 뒤 종료하므로, **참여형 문구·정답 개수 표시와 확인 후 종료**, 커트라인형/만점형의 서로 다른 문구·버튼을 정확하게 만족하는지 UI 검증 및 필요 시 분기 수정이 필요하다.

## 7. 추가 TODO — 참여형 퀴즈 채점 결과와 완료 상태 분리 (2026-11-09)

상태 **요구사항 정의 완료 / 구현 대기**. 이 절은 Q3의 참여형 `passingScore=0` 및 `passed=true` 고정 규칙을 신규 설정에 대해 대체한다. 기존 구현 기록은 당시 상태로 보존한다.

- [ ] **관리자·DB·조회** — `POPUP_NOTICE`에 E0090 퀴즈 유형 코드 컬럼을 추가해 `00·01·02`를 저장한다. 실제 유형 매핑은 공통코드 정의와 대조한다. 관리자 저장·재조회는 유형 코드를 사용해 참여형, 커트라인형, 만점형을 구분하고, 참여형도 설정한 `passingScore`를 보존한다. 기존 데이터의 유형은 기존 점수 기준으로 복원하며 만점 커트라인과 만점형처럼 구분할 수 없는 건은 이관 기준을 정한다. WPF 조회 응답의 `popup` 최상위에는 유형 코드에서 파생한 `requiresPassing`(boolean)만 추가한다. 참여형은 `false`(합격 기준과 무관하게 제출하면 완료), 커트라인형·만점형은 `true`(합격해야 제출·완료)다. SURVEY 등 QUIZ 외 유형에는 내려주지 않는다.
  - **필드 이름 결정(2026-11-09)**: 조회 응답에서 `passed`를 쓰는 안은 결과 요청의 `passed`(채점 합불)와 이름이 같고 참·거짓 의미가 반대로 읽혀 채택하지 않는다. 조회는 `requiresPassing`, 결과는 기존 `passed`를 유지한다.
- [ ] **WPF 채점·안내** — 유효한 응답에서 `passed = score >= passingScore`로 계산한다. `QuizResultNotice`는 `requiresPassing == false`이면 기준 미달이어도 참여 완료 안내와 정답 개수를 표시하고 확인 후 종료한다. `PopupManager.SubmitSurveyResult`는 합격이 필요한 퀴즈에서만 `requiresPassing && !passed`로 결과 전송을 막고 재응시를 안내한다. 만점형은 만점 기준으로 채점하며 기존 점수 기준의 만점형 안내를 유지한다. VIDEO+QUIZ의 제출 경로를 확인하고 시청 조건을 유지한다.
- [ ] **서버 결과 저장·완료** — 유효한 퀴즈 `SUBMITTED`는 `passed` 값과 관계없이 `COMPLETED`로 처리한다. `score`·`passed`는 채점 결과로 저장한다. 서버는 에이전트의 채점값과 제출 허용 판단을 신뢰한다. 기존 인증, 전달 건 매칭, 요청·답안 검증과 멱등 처리는 유지한다. 전달 건 정책 스냅샷, `WPF_POPUP_DELIVERY` 정책 컬럼 및 제출 시 정책 재조회는 범위에서 제외한다. 결과 API 요청·응답 JSON 구조는 유지한다.
- [ ] **구버전 호환·배포** — 신규 WPF가 `requiresPassing` 없는 조회 응답을 받으면 기존 점수 기반 유형 판정을 적용한다(`passingScore` 0 이하·미설정 = 참여형). 기준 점수가 없는 기존 참여형은 `passed: true` 동작을 유지한다. 구버전 WPF에 양수 기준 참여형을 전달하면 커트라인형처럼 미달 제출을 막고 재응시를 요구한다. Overlay가 켜진 경우 닫기 경로도 막힐 수 있다. 서버가 신규 결과를 처리할 수 있게 준비한 뒤 **신규 WPF 배포 → 관리자 웹의 참여형 양수 기준 입력 개방** 순서를 지킨다. 서버의 Agent 버전 식별 수단을 확인하고, 구버전이 남아 있다면 해당 팝업이 구버전에 전달되지 않도록 배포 조건을 정한다.
- [ ] **연관 문서·도구** — `WPF_POPUP_MINIMAL_SPEC`·`WPF_POPUP_ALL_SPEC`에 조회 `requiresPassing`을 반영하고 결과 `passed`(채점 합불)의 참여형 의미 변화를 적는다. 데모 JSON 검사기 `KnownTop`과 데모 샘플에 `requiresPassing`을 추가한다. DB 컬럼은 `db/oracle/23_…` 스크립트와 `01_popup_schema_oracle.sql`에 함께 반영한다. TODO73-4·§3-1과 `popupQuizRule.ts`의 "참여형 = `passingScore` 0, 기준 입력 없음" 서술을 정리하고 참여형 기준 개수 입력을 복원한다.
- [ ] **검증** — 3개 유형과 기준 점수의 관리자 저장·재조회, 만점 기준 커트라인과 만점형의 유형 보존을 확인한다. 참여형 기준 5점에서 3점을 받으면 `score: 3, passed: false`가 저장되고 `COMPLETED` 처리되어 다음 조회에서 제외되는지 확인한다. 기준과 같은 점수, 커트라인·만점형 미달 시 전송 차단, 합격 제출, 중복 전송, 구버전의 제출 차단과 Overlay 닫기, VIDEO+QUIZ 제출 경로를 검증한다.
