## 1. 확인된 현상과 비교 결과

아래 수치는 저사양 PC에서 작업 관리자로 확인해 전달된 근사값이다. 자동 벤치마크나 이 작업 환경에서 재현한 결과가 아니다. CPU 모델·GPU·DPI·정확한 표시 크기는 미수집 상태다.

| 조건 | CPU 관찰 | 해석 |
| --- | --- | --- |
| 기존 영상 팝업 재생 | 약 90~93% | 화면이 덜 부드러우나 재생 시간은 실제 시간과 일치 |
| 기존 영상 일시정지 | 약 80% | 디코딩 외 지속 부하 존재 |
| 영상 팝업 닫기 | 약 1% | 열린 영상 화면과 부하가 연관됨 |
| 다른 팝업 | 약 10% 내외 | 공통 기능만으로 영상의 높은 부하를 설명하기 어려움 |
| PowerShell 단순 MediaElement | 약 5~10% | .NET Framework 비교이므로 런타임 차이 있음 |
| 같은 프로젝트의 단순 MediaElement 창 | 약 10% | 같은 .NET 런타임에서도 단순 창은 낮은 부하 |
| 무한 로딩 애니메이션 제거 후 일시정지 | 약 1% | 로딩 애니메이션의 불필요한 실행 제거가 유효 |
| 위 상태에서 재생 | 약 80% | 재생 시 추가 렌더링 부하가 남음 |
| 위 상태에서 부모 Border.Effect 제거 후 재생 | 약 30% | 영상 포함 부모의 그림자 효과 제거가 유효 |
| 위 상태에서 AllowsTransparency=False, 나머지 옵션 복원 | 약 10% 내외 | 불투명 창 전환의 추가 효과 확인 |

- 동일 영상은 Windows Media Player에서 단독 재생 시 원활했다. 팝업과 동시 실행하면 WMP도 끊기는 현상이 있었다.
- 진행률 타이머, Windows 볼륨 동기화, 영상 위 UI, 배경 오버레이 제외 비교에서 뚜렷한 추가 개선은 보고되지 않았다. 영구적으로 불필요하다고 판단하거나 삭제할 근거는 아니다.
- 초기 AllowsTransparency 단독 비교에서는 차이가 없었다. 이후 애니메이션·그림자를 제거한 조건에서 효과가 확인되었다. 원래 코드에서 이 속성 하나만 변경하면 해결된다고 기록하지 않는다.
- 저장소 내장 MP4는 H.264 High / 592×252 / 24fps / 약 97.7초 / 약 9.4MB이며 FFmpeg 전체 디코딩 검사 오류가 없었다. 실제 배포 파일의 동일성은 별도 확인 대상이다.
- 데모는 EXE 옆 Media 파일을 우선 사용하며, 없으면 내장 리소스를 캐시에 추출한다. 로컬 파일은 MediaElement, HTTP/YouTube는 웹 재생 분기다.

## 6. 검증 및 완료 기준

- [ ] 같은 PC·같은 파일·같은 영상 표시 크기·같은 DPI·배속 1.0으로 비교한다. WMP/다른 테스트 창은 동시에 실행하지 않는다.
- [ ] CPU/GPU 모델, Windows/.NET/WebView2 버전, 모니터/DPI, 빌드 커밋 및 영상 파일 해시를 기록한다.
- [ ] 시작 직후 부하와 안정 재생 부하를 구분하고 30~60초 구간 CPU 범위·평균 및 체감 끊김을 기록한다. 재생 시간과 실제 시간이 일치하는지도 확인한다.
- [ ] 수정 전 / 애니메이션 수정 / 그림자 분리 / 불투명화 / 모든 기능 복원 결과를 비교한다.
- [ ] 목표는 해당 PC에서 단순 창에 가까운 안정 재생과 일시정지 시 유휴 수준 회복이다. 약 10%/1%는 관측 참고값이며 모든 PC의 절대 합격 기준으로 사용하지 않는다.
- [ ] VIDEO·VIDEO+QUIZ·전체화면 진입/복귀, 로컬/HTTP 재생, 오버레이 ON/OFF, 로딩·재버퍼링·오류·종료·재오픈을 검증한다.
- [ ] 재생 관련 UI·키보드/마우스·볼륨 동기화·시청률·닫기/제출 회귀를 확인한다.
- [ ] 불투명 창 전환 후 모서리·배경 사각형·그림자·제목줄·드래그·다중 모니터/DPI·항상 위 표시의 시각/입력 회귀를 확인한다.
- [ ] 수정 후에도 단순 창 대비 큰 차이가 남으면 CPU 프로파일링으로 실제 호출 스택을 확인한다. 원인 확인 없이 기능 제거를 반복하지 않는다.
- [ ] 빌드 및 필요한 회귀 검사 후 새 EXE를 같은 저사양 PC에서 확인한다. 테스트용 변경만으로 구현 완료를 표시하지 않는다.

## 7. 반영 결과 (2026-10-06)

- §2: XAML의 Loaded EventTrigger를 제거하고 `LoadingSpinnerRotate`에 대한 `SetLoadingAnimation(bool)` 하나로 시작/중지한다. 이미 실행 중이면 다시 시작하지 않고, 중지 시 `BeginAnimation(..., null)`로 clock을 제거한다. 로딩·버퍼링 표시(`ShowLoadingMessage`)에서만 시작하고, 안내 닫기(`HideVideoMessage`)·재생 차단 안내·오류·일시정지·재생 종료·Unloaded에서 중지한다. 전체화면 전환은 애니메이션 대상 Transform을 그대로 옮기므로 재시작·중복이 없다.
- §3·§4: `PopupWindow`가 생성자에서(핸들 생성 전) VIDEO/VIDEO+QUIZ 여부를 판단해 `AllowsTransparency=false`, 흰 배경, 그림자용 24px 여백 0, `DropShadowEffect` 제거, 모서리 0을 적용한다. 1px 테두리는 유지한다. 그 밖의 팝업 유형과 배경 오버레이 창, 별도 전체화면 창(원래 불투명·검정 배경·효과 없음)은 변경하지 않았다.
- 장식용 그림자(형제 요소·OS 창 그림자·Windows 11 DWM 모서리)는 저사양 PC 부하 비교와 시각 확인이 필요하므로 보류했다. 현재 영상 창은 사각 모서리이며, 헤더 닫기 버튼 hover의 오른쪽 위 둥근 모서리(템플릿 CornerRadius 16)는 사각 창에서 약간 어긋나 보일 수 있다.
- §5: 기준 커밋 a1d8a1e에는 임시 Collapsed/IsHitTestVisible 테스트 코드나 `OpenSimpleVideoTest` 호출이 없어 원복할 대상이 없음을 확인했다. 재생 UI·볼륨 동기화·시청률·닫기 제한 동작은 변경하지 않았다.
- 자동 검증: WPF 빌드 경고·오류 0. 행동 검증 798건(신규 23건: 유형별 창 불투명/그림자 정책, 로딩→준비→재버퍼링→일시정지→재생 차단→오류→Unloaded 순서의 애니메이션 clock 유무), 복구 122건, HTML5 bridge 89건 통과.
- 미실행: §6의 저사양 PC CPU 실측, 불투명 창 외형·드래그·다중 모니터/DPI·WebView2CompositionControl 표시 회귀의 실제 화면 확인, 새 EXE 반입. 이 항목들이 끝나기 전에는 현장 수치 개선을 확정하지 않는다.
