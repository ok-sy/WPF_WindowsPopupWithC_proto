## 기본 원칙과 작업 제한

1. **71-1~71-3은 조사·제안 단계다.** 이 단계에서 기능 코드, 기존 TODO, 계약서, 주석을 수정·삭제·이동하지 않는다. 검증표·제안 문서만 작성한다.
2. 기존 TODO 원본과 번호, 결정·폐기·대체 이력은 보존한다. 원본 파일 이동은 참조 경로 조사와 통합안 확정 이후 별도 단계에서 수행한다.
3. 정책 문서 통합을 이유로 기능·API/JSON·DB·WPF 동작, 기본값, 오류 정책을 임의 변경하지 않는다. 소스와 문서가 충돌하면 현행 코드만으로 정책을 확정하지 않고 **충돌/확인 필요**로 기록한다.
4. 단순히 최신 번호가 우선이라는 규칙은 사용하지 않는다. 확정 결정, 후속 대체, 현재 구현, 인터페이스 계약 및 검증 기록을 함께 확인한다.
5. 동일 TODO가 여러 정책에 걸치면 원본은 하나로 유지하고 **주 정책·연관 정책**을 구분한다. 카테고리 숫자에 맞추기 위한 강제 병합은 하지 않는다.
6. 테스트 미실행, DB 미적용, 폐쇄망 미검증, 타 팀 인계 미완료 등은 완료로 간주하지 않는다. `AGENTS.md`의 변경 이력·커밋 규칙을 따른다.
