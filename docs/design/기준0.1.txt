1. 본 설계는 https://github.com/ok-sy/WPF_WindowsPopupWithC_sample 저장소의 최신 소스를 기준으로 하며, 현재 구현된 팝업 구조와 기능을 기반으로 개선안을 설계한다.

2. 팝업 표시 대상 판단은 서버가 수행한다. 서버는 사용자, 대상 조건, 노출 기간, 활성 여부, 숨김 여부, 완료 여부 등을 판단하여 현재 WPF에서 실제로 표시해야 할 최종 팝업 목록만 반환한다. WPF는 서버에서 전달받은 JSON 데이터를 기반으로 팝업 화면을 렌더링하는 역할을 담당한다.

3. WPF가 팝업을 표시하기 위해 필요한 공통 옵션, 팝업 유형별 content, 문항 및 선택지 정보를 여러 API로 분리하지 않고 하나의 팝업 목록 조회 API 응답에 포함한다. 사용자 응답 및 팝업 처리 결과 역시 가능한 한 하나의 공통 결과 API를 통해 전달하는 구조로 단순화한다.

4. 서버 부하 및 실시간 통신 요구를 최소화하기 위해 VIDEO 진행률 실시간 전송, DISPLAYED/CLOSED 이벤트 실시간 로깅 등 반복 호출 방식은 제거한다. 서버 통신은 기본적으로 WPF 시작 또는 팝업 조회 시점과 팝업 종료·완료·응답 제출 시점에 수행한다.

5. 현재 PostgreSQL 기반으로 구성된 popup 관련 데이터베이스 구조를 Oracle 기준으로 변환한다. PostgreSQL 전용 데이터 타입, JSON 저장 방식, 시퀀스/Identity, 날짜 처리 및 SQL 문법은 운영 Oracle 버전에 적합한 방식으로 재설계한다.

6. WPF는 기존 Zero 웹 로그인과 분리된 WPF 전용 인증 영역을 사용한다. SSO 인증을 기반으로 WPF 전용 Access Token을 발급받고, 이후 /p/** API 호출 시 Authorization: Bearer 방식으로 전달한다. 사용자 식별은 가능한 한 Request의 userId 값이 아닌 인증 토큰의 사용자 정보를 기준으로 처리한다.

7. 관리자 웹은 팝업 등록·수정, 대상 조건 설정 및 콘텐츠 구성을 담당하고, 서버는 팝업 데이터 저장과 노출 대상 계산을 담당하며, WPF는 최종 팝업 JSON 수신·렌더링·사용자 응답 수집 및 최종 결과 전송을 담당한다.
