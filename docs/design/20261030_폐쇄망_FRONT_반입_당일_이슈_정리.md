## 1. 패키지 설치 및 배포 방식

- `pnpm install --offline --frozen-lockfile`은 `package.json`과 `pnpm-lock.yaml` importer specifier가 일치하지 않아 실패.
- `pnpm install --lockfile-only --offline` 시 일부 의존성의 오프라인 레지스트리 메타데이터를 찾지 못함.
- 실제 폐쇄망 `node_modules`에는 `ckeditor5@44.3.0`, `@ckeditor/ckeditor5-react@5.1.0`이 존재하고 `require.resolve()`가 정상 경로 반환. 관련 폴더 `LinkType`은 공백.
- 반입 목표는 `ckeditor5@49.0.1`, `@ckeditor/ckeditor5-react@12.0.0`. 새 패키지의 **전체 실행 의존성**과 기존 에디터 호출부 전환이 함께 필요. **당일 교체 완료로 기록하지 않음.**
- `node_modules` 직접 복사는 lockfile 검사 없이 파일을 배치할 수 있지만 의존성 일관성·향후 설치 재현을 보장하지 않으므로, 최종 package.json 세트와 lockfile 정합성 TODO는 유지.
- 상세 절차: [폐쇄망 pnpm workspace/lockfile 불일치 해결 TODO](20261030_폐쇄망_pnpm_workspace_lockfile_불일치_해결_TODO.md).

- MUI Icon 전체 네임스페이스 import 대신 개별 icon import로 최적화하는 변경 적용.

## 3. 메인 배경색 충돌 — 실제 화면 확인

원본 전역 CSS: `main/src/styles/globalStyle.ts`

```css
body { background: #ebebeb; }
```

동적으로 생성된 Emotion 전역 CSS: `main/pages/_app.tsx`의 `<CssBaseline />` 관련

```css
body { background-color: #fff; }
```

- DevTools `Sources (index)`에서 `<style data-emotion="css-global ...">` 내부의 `background-color: #fff`가 확인됨.
- `Elements > Styles`에서 흰색 속성을 비활성화하면 기존 회색 배경 복구.
- 두 규칙은 동일한 `body` 선택자에 적용되므로 **실제 CSS 삽입 순서와 선언 우선순위**에 따라 결과가 달라짐.
- Webpack 재구성에서도 같은 증상이 나왔으므로 특정 번들러 하나의 버그로 확정하지 않음.
- **임시 `!important`, 임의의 `MainLayout`/ `NotReady` 배경 고정은 최종 수정으로 채택하지 않음.** 글로벌 CSS와 Theme/`CssBaseline`의 배경 정책을 일치시키고, 수정 후 양쪽 실행 모드에서 확인 필요.
- `MainLayout-root`, `CloverMainHome-root`가 투명한 것은 원래 `body` 전역 배경과 별개이므로 무관한 레이아웃 배경 강제 추가는 피함.

### 3-1. 원인 확인(로컬 재현) 및 수정

- 단서: 폐쇄망 DevTools의 키가 `css-global`. 이 프로젝트의 MUI 캐시(`AppCacheProvider`/`documentGetInitialProps`)는 키가 `mui`이므로 정상이면 `mui-global`이어야 함 → MUI가 앱 캐시를 쓰지 못하고 emotion 기본 캐시(`css`)로 동작 중.
- 로컬 재현(`next dev --turbopack`, 임시 전역 CSS `body { background-color }`): Turbopack SSR이 `@mui/material-nextjs/v15-pagesRouter`만 외부(CJS)로 불러오고 `@mui/material`·`@emotion/react`는 번들(ESM)해 emotion 인스턴스가 둘로 갈림. 그 결과 `css-global`(CssBaseline) 스타일이 `<body>` 안에 인라인 출력돼 `<head>`의 전역 CSS 뒤에 놓이고 `body` 규칙을 덮어씀.
- 수정: `main/next.config.mjs`의 `transpilePackages`에 `@mui/material-nextjs` 추가. 수정 후 `mui-global`이 `<head>`의 `emotion-insertion-point` 바로 뒤(전역 CSS 앞)에 위치하고 `css` 키 스타일 0건 확인. `next build` 성공.
- 폐쇄망 확인 방법: 반영 후 DevTools에서 `data-emotion` 키가 `mui-global`/`mui ...`로 바뀌고 `<head>` 안에 있는지 확인.
- Webpack에서도 `css-global`이 남으면 번들러 차이가 아니라 `@emotion/react`가 물리적으로 둘 이상(수동 node_modules 복사로 중첩 설치 등)인 경우를 의심: `node_modules` 아래 `@emotion/react/package.json`이 하나인지 확인.
- 전역 CSS가 `.ts`(`globalStyle.ts`)라면 적용 방식(`<style jsx global>`, emotion `Global`, `injectGlobal` 등)에 따라 삽입 위치가 다르므로 실제 코드 확인 필요. 순서와 무관하게 맞추려면 배경색을 Theme(`palette.background.default`)에 두는 방법도 있으나 폐쇄망 색상 정책 확인 후 결정.
