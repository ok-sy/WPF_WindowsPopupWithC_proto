## 목적과 범위

흰 문항 카드와 옅은 회색 콘텐츠 배경은 유지하고, 어떤 선택지를 골랐는지와 몇 개를 고를 수 있는지를 명확하게 한다. FONT EDIT의 색·굵기·기울임을 보존하면서 선택 상태와 키보드 포커스를 구분한다.

대상: SurveyPopupView를 공유하는 SURVEY·QUIZ·VIDEO+QUIZ의 세로형 선택지와 가로형 Chip, 필수 응답 안내. WPF 구현·검증·샘플 전달을 담당 범위로 하고 관리자 웹 미리보기는 Front 담당자에게 동기화 기준을 전달한다. 서버 계약·결과 유형·채점·완료 정책 변경은 포함하지 않는다.

## 현재 확인한 내용

- 콘텐츠 배경 #F5F6F8, 문항 카드/선택지 흰색, 기본 글자 #222222, 선택 강조 #171717은 2026-10-18-09에 반영됐다.
- 세로형/Chip 모두 선택 전에도 옅은 체크가 보인다. 공간 예약 목적이지만 미선택과 선택을 혼동할 수 있다.
- 라디오와 체크박스가 같은 기반 템플릿을 공유해 단일/복수 선택의 시각적 차이가 작다.
- 선택 시 SemiBold, 포커스 시 테두리 덮어쓰기 등이 있어 FONT EDIT 서식과 줄바꿈·선택 강조의 관계를 점검해야 한다.
- TODO55에 서식 선택지의 선택 전후 높이가 달라질 수 있다는 미확인 항목이 있다.
- 현재 자동 검증 통과 기록은 이 TODO의 변경 완료나 실제 Windows 화면 검증을 의미하지 않는다.

## 표시 기준

| 구분 | 미선택 | 선택됨 |
|---|---|---|
| 단일 선택 | 빈 원 | 원 안의 점 |
| 복수 선택 | 빈 사각형 | 사각형 안의 체크 |
| 선택지 표면 | 흰색 + 연한 테두리 | 흰색 + 명확한 강조 테두리 |

- 선택 전에는 점·체크를 표시하지 않는다. 표시기 영역의 폭·높이는 예약한다.
- 문항에 “하나 선택” / “여러 개 선택 가능”을 보조 안내한다. 실제 선택 개수 제한이 있으면 기존 계약의 제한과 일치시키고 임의의 제한을 추가하지 않는다.
- 선택 여부는 표시기와 테두리로 전달한다. 사용자 지정 글자색을 선택색으로 덮거나 선택 때문에 본문 굵기·크기를 바꾸지 않는다.
- 포커스는 별도 외곽선 등으로 구분해 선택 강조와 동시에 인식할 수 있게 한다.
- 표시기 위치는 세로/가로 템플릿의 읽기 순서와 긴 문구를 비교해 정한다. 위치 통일 자체보다 표시기 종류·상태 의미의 일관성을 우선한다.
