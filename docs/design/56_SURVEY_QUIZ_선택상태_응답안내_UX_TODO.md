## 목적과 범위

중첩 문항 카드를 줄이고 흰 본문·간격·구분선으로 문항을 나누며, 어떤 선택지를 골랐는지와 몇 개를 고를 수 있는지를 명확하게 한다. FONT EDIT의 색·굵기·기울임을 보존하면서 선택 상태와 키보드 포커스를 구분한다.

대상: SurveyPopupView를 공유하는 SURVEY·QUIZ·VIDEO+QUIZ의 세로형 선택지와 가로형 Chip, 필수 응답 안내. WPF 구현·검증·샘플 전달을 담당 범위로 하고 관리자 웹 미리보기는 Front 담당자에게 동기화 기준을 전달한다. 서버 계약·결과 유형·채점·완료 정책 변경은 포함하지 않는다.

## 표시 기준

| 구분 | 미선택 | 선택됨 |
|---|---|---|
| 단일 선택 | 별도 원형 표시기 없음 | 진한 선택지 테두리 |
| 복수 선택 | 별도 사각형 표시기 없음 | 진한 선택지 테두리 |
| 선택지 표면 | 흰색 + 연한 테두리 | 흰색 + 명확한 강조 테두리 |

- 라디오 원·점과 체크박스 사각형은 표시하지 않고 전용 예약 공간도 제거한다. 선택 전 체크는 표시하지 않는다. 최신 캡처의 선택된 세로형 오른쪽 체크는 기존 보조 표현으로 두되 필수 기준으로 삼지 않으며 이번 카드 정리와 별개로 다룬다.
- 문항에 “하나 선택” / “여러 개 선택 가능”을 보조 안내한다. 실제 선택 개수 제한이 있으면 기존 계약의 제한과 일치시키고 임의의 제한을 추가하지 않는다.
- 선택 여부는 진한 테두리로 전달한다. 사용자 지정 글자색을 선택색으로 덮거나 선택 때문에 본문 굵기·크기를 바꾸지 않는다.
- 포커스는 별도 외곽선 등으로 구분해 선택 강조와 동시에 인식할 수 있게 한다.
- 단일/복수는 문항 보조 안내로 구분한다. 내부 RadioButton/CheckBox 의미와 키보드·접근성 동작은 유지한다.

## 2026-10-18 후속 결정: 문항 카드 중첩 축소

기준: 23:23 공유 화면. 선택지 안의 기본 라디오·체크박스를 없앤 방향은 유지한다. 흰 문항 카드 안에 다시 둥근 선택지를 넣는 반복 구성을 줄여 실제 업무용 설문에 맞는 화면으로 정리한다. 기능 검증용 서식 데이터와 디자인 평가용 데이터를 분리한다.

### 56-10 문항 카드 제거 및 문항 구분
- [ ] 본문 기본 배경을 흰색으로 두고 각 문항의 흰색 둥근 카드 표면을 제거한다.
- [ ] 문항은 일정한 세로 간격과 얇은 중립색 구분선으로 구분한다. 마지막 문항 뒤의 불필요한 선은 생략한다.
- [ ] 카드 Padding 제거 시 본문 좌우 여백까지 사라지지 않게 한다. 문항 번호·제목·선택지 시작선을 정리한다.
- [ ] 헤더·푸터까지 일괄 재디자인하지 않는다. 본문 경계와 고정 푸터 구분에 필요한 최소 표현만 조정한다.

### 56-11 선택지 라운드 축소
- [ ] 선택지와 Chip의 둥근 정도를 줄인다. 초기 비교값은 4~6 DIP이며 최종 값은 실화면으로 결정한다.
- [ ] 선택지의 흰 배경·연한 기본 테두리·진한 선택 테두리를 유지한다.
- [ ] 크기를 줄이기 위해 클릭 영역·행 높이를 과도하게 줄이지 않는다. 긴 선택지의 줄바꿈과 FONT EDIT 여유를 유지한다.
- [ ] 색·그림자·배지 등 장식을 추가하지 않는다. 짧은 세로형 선택지를 임의로 Chip으로 바꾸거나 서버가 지정한 배치를 바꾸지 않는다.

### 56-12 문항 안내 배치 정리
- [ ] “하나 선택” / “여러 개 선택 가능”을 제목 옆 보조 문구로 옮겨 반복되는 한 줄을 줄인다.
- [ ] 제목이 길거나 창이 좁으면 보조 문구를 다음 줄로 자연스럽게 배치한다. 겹침·말줄임으로 정보를 잃지 않는다.
- [ ] 문항 번호·필수 표시·선택 안내의 시각적 우선순위를 제목보다 낮게 유지한다.
- [ ] 서식 제목의 다중 문단과 들여쓰기 데이터를 바꾸지 않고 화면 배치로 처리한다.

### 56-13 디자인 평가용 샘플 분리
- [ ] 실제 교육 만족도 설문 문구, 기본 검정 글자, 필요한 최소 강조만 있는 디자인 평가용 샘플을 준비한다.
- [ ] 긴 영문 문자열·다색 글자·기울임·들여쓰기·혼합 크기 샘플은 서식 검증용으로 유지한다. 해당 기능이나 데이터를 삭제하지 않는다.
- [ ] 같은 데이터·창 크기·DPI·선택 상태로 기존/변경 화면을 비교해 카드 중첩, 문항 구분, 선택 인지, 화면 밀도를 확인한다.
- [ ] 먼저 문항 카드 제거와 라운드 축소를 비교하고, 이후 안내 배치를 확인한다. 여러 장식을 동시에 바꿔 평가 원인을 흐리지 않는다.

### 56-14 기존 디자인 버전 및 검증 경계
- [ ] 현재 SurveyDesign/SurveyDesigns 버전 구조를 확인해 기존 디자인을 보존하고 후속 디자인을 별도 버전으로 관리한다. 구현 시 이미 추가된 버전 번호와 충돌하지 않게 한다.
- [ ] API 계약이나 팝업 콘텐츠에 디자인 필드를 추가하지 않고 기존 WPF 설정 선택 구조를 사용한다. 기본 버전 변경 여부는 구현 결과와 함께 명시한다.
- [ ] 최초/최하단 스크롤에서 첫 문항과 마지막 문항 전체에 접근할 수 있는지 확인한다.
- [ ] 기존 56-3~9의 선택·포커스·서식·제출·DPI 검증을 재사용한다. 카드 제거만으로 답변·채점·완료 정책을 바꾸지 않는다.
- [ ] WPF 비교 캡처 및 디자인 기준을 Front 담당자 인계 항목으로 남기고 웹 반영 완료와 구분한다.
