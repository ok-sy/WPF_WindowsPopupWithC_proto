# 08. 관리자 웹(zeroweb) 변경 설계

기준 항목 7: 관리자 웹은 팝업 등록·수정, 대상 조건 설정, 콘텐츠 구성을 담당한다. 이 역할은 **현행 구현이 이미 수행**하고 있으므로 zeroweb 변경은 최소다. 관리자 API(`/apis/popup/**`) 6개와 응답 래퍼(`CLNewApiResponse`)는 그대로 유지한다.

## 1. 변경 필요 여부 점검

| 기준 | 관리자 웹 영향 | 결론 |
|---|---|---|
| 2 서버가 노출 판단 | 관리자 웹은 원래 노출 판단을 하지 않음 | 변경 없음 |
| 3 조회·결과 API 통합 | WPF API 변경. 관리자 API는 별도 경로 | 변경 없음 |
| 4 실시간 통신 제거 | WPF 측 | 변경 없음 |
| 5 Oracle 전환 | 서버 매퍼가 흡수. 관리자 API JSON 계약 동일 | 변경 없음. 날짜가 epoch 숫자로 오는 현행 처리 유지 |
| 6 WPF 인증 | 관리자 웹 로그인(`/p/api/auth/login`)과 분리 | 변경 없음 |
| 7 역할 분담 | 이미 충족 | 변경 없음 |

## 2. 권고 수정 1건 (선택, 최소)

참조 저장소 `ERD/STRUCTURE_REVIEW.md` P0 "SURVEY 채점 제거"가 미반영 상태다. 결과 API(03 문서)는 SURVEY 제출을 채점 없이 즉시 완료 처리하므로, 관리자 화면에서 SURVEY에 채점 입력이 노출되면 저장값이 무시되어 혼란을 준다.

| 파일 | 수정 | 방식 |
|---|---|---|
| `zero-rule-web/main/src/features/RgstPop/PopupQuestionEditor.tsx` | `popupType === 'SURVEY'`일 때 채점 여부 토글·배점·정답 입력을 렌더링하지 않음 | 조건부 렌더링 **추가**. 상태 구조·저장 payload 형식 변경 없음 |
| `zero-rule-web/main/src/features/RgstPop/PopupEditorDialog.tsx` | SURVEY일 때 통과 점수 입력 비표시 | 동일 |

```tsx
{/* [WPF 개선 — 결과 API 정합성] SURVEY는 서버가 채점하지 않고 제출 즉시 완료 처리한다(docs/03 §4).
    QUIZ에서만 채점 옵션을 보여 저장값과 동작이 어긋나지 않게 한다. 저장 데이터 구조는 바꾸지 않는다. */}
{popupType === 'QUIZ' && (
  <ScoringOptions ... />
)}
```

서버 측 정규화(SURVEY 저장 시 `isScored=false`, `passingScore=null` 강제)는 기존 `PopupService.saveAdminQuestions`/`PopupQuestionRules`를 수정해야 하므로 이번 범위에서는 **하지 않고** 09 문서 미결로 이관한다. 결과 API가 SURVEY를 채점하지 않으므로 기존 데이터에 채점 문항이 남아 있어도 동작에는 영향이 없다.

## 3. 미리보기 정합성 확인 항목

`PopupPreview.tsx`는 WPF 렌더링과 같은 JSON을 소비한다. 신규 WPF 조회 응답이 `content.questions`를 제거하고 최상위 `questions`만 제공하지만, 관리자 상세 API(`/apis/popup/info`)는 현행대로 두 곳에 모두 제공하므로 미리보기는 영향이 없다. 확인만 한다.
