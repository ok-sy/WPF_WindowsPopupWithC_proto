# 05. Oracle DB 설계 — PostgreSQL popup 스키마 변환

기준 항목 5. 스크립트: [db/oracle/01_popup_schema_oracle.sql](../db/oracle/01_popup_schema_oracle.sql), 샘플: [db/oracle/02_popup_sample_oracle.sql](../db/oracle/02_popup_sample_oracle.sql).

전제: 설계 시 **Oracle 19c**로 가정했으나 **2026-09-20 원격 개발 DB 실측은 11g XE 11.2.0.2**. DDL을 11g 호환으로 조정했다 — 제약명 30자 이하(`UK_QTEMPLATE_GROUP_VERSION`·`CK_TCOND_INCLUDE_CHILD`·`CK_TCOND_CHILD_DEPARTMENT`), `IS JSON` 체크 제거(JSON 유효성은 `PopupContentAssembler`). 매퍼 SQL은 원래 11g 문법 범위(MERGE·함수 기반 인덱스·재귀 WITH·`SYSTIMESTAMP AT TIME ZONE`)다. 테이블·컬럼 구성은 원본과 동일하게 유지하고, 신설은 `WPF_RESULT_RECEIPT` 1개다. 인증용 테이블·컬럼은 만들지 않는다 (04 문서).

## 1. 스키마 배치

| PostgreSQL | Oracle | 비고 |
|---|---|---|
| 스키마 `zero_rule` (공통 53개) | 기존 운영 Oracle의 zero 프레임워크 스키마 | 원본 DDL 주석(`-- Oracle table: ...`)과 `libs.versions.toml`의 ojdbc 항목으로 zero 프레임워크가 Oracle 출신임을 확인. **이번 변환 범위 외** |
| 스키마 `popup` (16개) | 사용자/스키마 `POPUP` (16 + 신설 1) — **또는** 앱 계정 스키마 안(2026-09-20) | 매퍼는 `${popupSchemaPrefix}` 변수로 한정자를 붙인다. 설정 `custom.popup.schema`가 `POPUP`(기본)이면 `POPUP.`, 빈 값이면 한정자 없음. 원격 개발 DB는 앱 계정 `zero-rule`에 CREATE USER 권한이 없어 빈 값(팝업 테이블을 그 계정 스키마에 생성). 계산은 `PopupSchema`, 주입은 `MyBatisConfig`(추가 4줄) |

## 2. 데이터 타입 변환 규칙

| PostgreSQL | Oracle | 적용 컬럼 | 비고 |
|---|---|---|---|
| `VARCHAR(n)` | `VARCHAR2(n CHAR)` | 전체 | 문자 단위 길이 보존 (NLS_LENGTH_SEMANTICS 무관) |
| `CHAR(1)` | `CHAR(1)` | Y/N 플래그 | 동일 |
| `TEXT` | `CLOB` | `content_body`, `correct_answer`, `text_answer`, 로그 3컬럼 | MyBatis는 `String` ↔ CLOB 자동 매핑 (ojdbc8) |
| `JSONB` | `CLOB` + `CHECK (col IS JSON)` | `popup_content.content_options` | 12.1+ 지원. JSON 조립·병합은 Java에서 수행 (§4.3) |
| `BIGINT GENERATED BY DEFAULT AS IDENTITY` | `NUMBER(19)` + 시퀀스 `SEQ_<TABLE>` | 대리키 11개 + 신설 1개 | IDENTITY(12c)도 가능하나 MyBatis `selectKey`로 키를 얻기 위해 명시적 시퀀스 채택 (§4.1) |
| `INTEGER` | `NUMBER(10)` | | |
| `NUMERIC(p,s)` | `NUMBER(p,s)` | 크기·비율·점수·초 | 동일 정밀도 |
| `TIMESTAMP` | `TIMESTAMP(6)` | 전체 | 시간대 없는 **KST 로컬 시각** 저장 (§3) |
| `DATE` | `DATE` | `hire_date`, `condition_date_value` | 시각 00:00:00. 비교 시 `TRUNC` 불필요 (입력 시 보장) |
| `BOOLEAN` (SELECT 결과) | `NUMBER(1)` 1/0 또는 `CHAR(1)` | 매퍼 계산 컬럼 | Java에서 `isYes()` 변환 (현행 방식 유지) |

## 3. 날짜·시간대 처리 (구현 반영 2026-09-19)

현행 PostgreSQL 매퍼는 모든 SELECT에 `col AT TIME ZONE 'Asia/Seoul'`을 붙여 `OffsetDateTime`으로 받는다. Oracle에서는 **Java 타입(`OffsetDateTime`)과 resultMap을 그대로 유지**하고 변환 지점만 바꾼다.

| 항목 | 결정 |
|---|---|
| 저장 컬럼 | `TIMESTAMP(6)`, 값은 항상 KST 로컬 시각 (시간대 없음) |
| 조회 | `FROM_TZ(col, 'Asia/Seoul')`로 `TIMESTAMP WITH TIME ZONE`을 내려 MyBatis 기본 `OffsetDateTimeTypeHandler`가 `OffsetDateTime(+09:00)`으로 읽음. resultMap `javaType` 변경 없음 |
| 바인드 (OffsetDateTime → 컬럼) | `#{x, typeHandler=server.repo.core.mapper.popup.KstTimestampTypeHandler}` — 어떤 오프셋으로 들어와도 KST 벽시계 시각으로 바꿔 `setTimestamp`. SQL 안 `AT TIME ZONE`은 NULL 바인드 시 타입 오류 위험이 있어 Java 핸들러로 처리 |
| 현재 시각 | 매퍼 공통 조각 `<sql id="nowKst">CAST(SYSTIMESTAMP AT TIME ZONE 'Asia/Seoul' AS TIMESTAMP)</sql>` — 세션·DB 서버 시간대와 무관. DDL `DEFAULT`도 같은 식 사용 |
| 일수 가산 | `nowKst + NUMTODSINTERVAL(#{hideDays}, 'DAY')` |
| 커넥션 | `JndiResource`에서 `ALTER SESSION SET TIME_ZONE='Asia/Seoul'`, `oracle.jdbc.timezoneAsRegion=false`를 초기화 SQL·속성으로 지정 (보조 안전장치) |

## 4. SQL 문법 변환 패턴

### 4.1 대리키 생성 — `RETURNING` → `selectKey`

```xml
<!-- PostgreSQL 원본: <select id="insertAdminTargetGroup" resultType="long">
                       INSERT ... VALUES (...) RETURNING target_group_id -->

<!-- Oracle: 시퀀스로 키를 먼저 얻어 파라미터 객체에 채운 뒤 INSERT -->
<insert id="insertAdminTargetGroup" parameterType="map">
    <selectKey keyProperty="targetGroupId" resultType="long" order="BEFORE">
        SELECT POPUP.SEQ_POPUP_TARGET_GROUP.NEXTVAL FROM DUAL
    </selectKey>
    INSERT INTO POPUP.POPUP_TARGET_GROUP
        (TARGET_GROUP_ID, POPUP_ID, TARGET_NAME, TARGET_DESCRIPTION, GROUP_ORDER, CREATED_BY, UPDATED_BY)
    VALUES (#{targetGroupId}, #{popupId}, #{targetName}, #{targetDescription}, #{groupOrder}, #{auditUser}, #{auditUser})
</insert>
```

매퍼 인터페이스는 `Long insert...(...)` 반환 대신 `int insert...(Map params)` 후 `params.get("targetGroupId")`로 키를 읽는다. **기존 `PopupService`의 호출부는 매퍼 인터페이스에 default 메서드로 기존 시그니처를 유지**해 서비스 수정을 피한다:

```java
/** [Oracle 전환 — 기준 5] RETURNING 제거로 키 반환 방식이 바뀌었으나
 *  PopupService의 기존 호출 시그니처(Long 반환)를 유지하기 위한 어댑터. */
default Long insertAdminTargetGroup(String popupId, String targetName, String targetDescription,
                                    int groupOrder, String auditUser) {
    Map<String, Object> p = new HashMap<>(Map.of("popupId", popupId, "targetName", targetName,
            "targetDescription", targetDescription, "groupOrder", groupOrder, "auditUser", auditUser));
    insertAdminTargetGroupOracle(p);
    return (Long) p.get("targetGroupId");
}
```

### 4.2 UPSERT — `ON CONFLICT DO UPDATE` → `MERGE`

```sql
-- 원본 upsertPopupHide (user_popup_status)
MERGE INTO POPUP.USER_POPUP_STATUS s
USING (SELECT #{userId} AS EMPLOYEE_NO, #{popupId} AS POPUP_ID FROM DUAL) src
   ON (s.EMPLOYEE_NO = src.EMPLOYEE_NO AND s.POPUP_ID = src.POPUP_ID)
WHEN MATCHED THEN UPDATE SET
     s.POPUP_STATUS    = 'HIDDEN',
     s.HIDDEN_FROM_AT  = SYSTIMESTAMP,
     s.HIDDEN_UNTIL_AT = SYSTIMESTAMP + NUMTODSINTERVAL(#{hideDays}, 'DAY'),
     s.UPDATED_BY      = #{userId},
     s.UPDATED_AT      = SYSTIMESTAMP
WHEN NOT MATCHED THEN INSERT
     (USER_POPUP_STATUS_ID, EMPLOYEE_NO, POPUP_ID, POPUP_STATUS, DISPLAY_COUNT,
      HIDDEN_FROM_AT, HIDDEN_UNTIL_AT, COMPLETED_YN, CREATED_BY, UPDATED_BY)
     VALUES
     (POPUP.SEQ_USER_POPUP_STATUS.NEXTVAL, src.EMPLOYEE_NO, src.POPUP_ID, 'HIDDEN', 0,
      SYSTIMESTAMP, SYSTIMESTAMP + NUMTODSINTERVAL(#{hideDays}, 'DAY'), 'N', #{userId}, #{userId})
```

`EXCLUDED.col` → `src.col` 또는 파라미터 재참조. `GREATEST(current.x, EXCLUDED.x)` → `GREATEST(s.x, #{x})`. 원본의 "완료 상태 되돌리지 않음" CASE 로직은 그대로 옮긴다.

`upsertPopupResponse`(RETURNING response_id)는 MERGE 후 `SELECT RESPONSE_ID FROM POPUP_RESPONSE WHERE EMPLOYEE_NO=… AND POPUP_ID=…`를 별도 `<select>`로 두고 매퍼 default 메서드로 묶는다.

### 4.3 content JSON 조립 — `JSONB_BUILD_OBJECT || content_options` → Java

원본 매퍼는 `popup_type`별 정규 컬럼을 JSON 객체로 만들고 `content_options`와 병합해 `content_json` 문자열을 반환한다. Oracle의 `JSON_OBJECT`/`JSON_MERGEPATCH`(19c)로 옮길 수 있지만 **버전 의존을 피하기 위해 Java로 이동**한다.

- 매퍼: `CONTENT_TITLE, DESCRIPTION, CONTENT_BODY, MEDIA_URL, LINK_URL, CONTENT_OPTIONS`를 개별 컬럼으로 반환 (resultMap `PopupEntity`에 6개 필드 추가 — 기존 `contentJson` 필드는 유지하되 null).
- Java: `PopupContentAssembler.assemble(popupType, entity)`(신규 클래스)가 현행 SQL과 동일한 키 매핑(TEXT→`contentTitle/plainText`, IMAGE→`imageTitle/imageUrl/linkUrl`, VIDEO→`videoTitle/videoUrl`, SURVEY/QUIZ→`surveyTitle`)으로 `Map`을 만든 뒤 `content_options`를 덮어쓰기 병합한다.
- 기존 `PopupService.parseContentJson`은 `entity.contentJson()`이 null이면 `PopupContentAssembler`를 호출하도록 **1개 분기 추가** (수정 최소).

### 4.4 노출 대상 조회 — 재귀 CTE·`BOOL_AND` 변환

```sql
WITH DEPARTMENT_TREE (ANCESTOR_DEPARTMENT_ID, DESCENDANT_DEPARTMENT_ID) AS (
    SELECT DEPARTMENT_ID, DEPARTMENT_ID FROM POPUP.APP_DEPARTMENT
    UNION ALL
    SELECT t.ANCESTOR_DEPARTMENT_ID, c.DEPARTMENT_ID
      FROM DEPARTMENT_TREE t
      JOIN POPUP.APP_DEPARTMENT c ON c.PARENT_DEPARTMENT_ID = t.DESCENDANT_DEPARTMENT_ID
),
SELECTED_USER AS (
    SELECT * FROM POPUP.APP_USER WHERE EMPLOYEE_NO = #{userId} AND ACTIVE_YN = 'Y'
),
CONDITION_RESULT AS (
    SELECT n.POPUP_ID, g.TARGET_GROUP_ID,
           CASE c.CONDITION_TYPE
             WHEN 'DEPARTMENT' THEN
               CASE c.CONDITION_OPERATOR
                 WHEN '='  THEN CASE WHEN c.INCLUDE_CHILD_YN = 'Y'
                                     THEN CASE WHEN EXISTS (SELECT 1 FROM DEPARTMENT_TREE t
                                                             WHERE t.ANCESTOR_DEPARTMENT_ID = c.DEPARTMENT_ID
                                                               AND t.DESCENDANT_DEPARTMENT_ID = u.DEPARTMENT_ID) THEN 1 ELSE 0 END
                                     ELSE CASE WHEN u.DEPARTMENT_ID = c.DEPARTMENT_ID THEN 1 ELSE 0 END END
                 WHEN '!=' THEN /* 위의 부정 */ ...
                 ELSE 0 END
             WHEN 'POSITION'  THEN CASE WHEN (c.CONDITION_OPERATOR = '='  AND u.POSITION_ID =  c.POSITION_ID)
                                          OR (c.CONDITION_OPERATOR = '!=' AND u.POSITION_ID <> c.POSITION_ID) THEN 1 ELSE 0 END
             WHEN 'EMPLOYEE'  THEN CASE WHEN (c.CONDITION_OPERATOR = '='  AND u.EMPLOYEE_NO =  c.EMPLOYEE_NO)
                                          OR (c.CONDITION_OPERATOR = '!=' AND u.EMPLOYEE_NO <> c.EMPLOYEE_NO) THEN 1 ELSE 0 END
             WHEN 'HIRE_DATE' THEN CASE WHEN (c.CONDITION_OPERATOR = '='  AND u.HIRE_DATE =  c.CONDITION_DATE_VALUE)
                                          OR (c.CONDITION_OPERATOR = '!=' AND u.HIRE_DATE <> c.CONDITION_DATE_VALUE)
                                          OR (c.CONDITION_OPERATOR = '<'  AND u.HIRE_DATE <  c.CONDITION_DATE_VALUE)
                                          OR (c.CONDITION_OPERATOR = '<=' AND u.HIRE_DATE <= c.CONDITION_DATE_VALUE)
                                          OR (c.CONDITION_OPERATOR = '>'  AND u.HIRE_DATE >  c.CONDITION_DATE_VALUE)
                                          OR (c.CONDITION_OPERATOR = '>=' AND u.HIRE_DATE >= c.CONDITION_DATE_VALUE) THEN 1 ELSE 0 END
             ELSE 0
           END AS CONDITION_MATCHED
      FROM SELECTED_USER u
      CROSS JOIN POPUP.POPUP_NOTICE n
      JOIN POPUP.POPUP_TARGET_GROUP g     ON g.POPUP_ID = n.POPUP_ID
      JOIN POPUP.POPUP_TARGET_CONDITION c ON c.TARGET_GROUP_ID = g.TARGET_GROUP_ID
     WHERE n.ACTIVE_YN = 'Y'
       AND SYSTIMESTAMP BETWEEN n.DISPLAY_START_AT AND n.DISPLAY_END_AT
       AND (n.QUESTION_TEMPLATE_ID IS NULL OR EXISTS (SELECT 1 FROM POPUP.QUESTION_TEMPLATE t
                                                        WHERE t.QUESTION_TEMPLATE_ID = n.QUESTION_TEMPLATE_ID AND t.ACTIVE_YN = 'Y'))
       AND NOT EXISTS (SELECT 1 FROM POPUP.USER_POPUP_STATUS s
                        WHERE s.EMPLOYEE_NO = u.EMPLOYEE_NO AND s.POPUP_ID = n.POPUP_ID
                          AND (s.HIDDEN_UNTIL_AT > SYSTIMESTAMP        -- 숨김 (원본 동일)
                               OR s.COMPLETED_YN = 'Y'))               -- [추가 — 기준 2] 완료 제외를 서버로 이동
),
ELIGIBLE_POPUP AS (
    SELECT POPUP_ID FROM CONDITION_RESULT
     GROUP BY POPUP_ID, TARGET_GROUP_ID
    HAVING MIN(CONDITION_MATCHED) = 1                                    -- BOOL_AND → MIN(1/0) = 1
)
SELECT ... FROM (SELECT DISTINCT POPUP_ID FROM ELIGIBLE_POPUP) e
  JOIN POPUP.POPUP_NOTICE n ON n.POPUP_ID = e.POPUP_ID
  LEFT JOIN POPUP.POPUP_CONTENT ct ON ct.POPUP_ID = n.POPUP_ID
 ORDER BY n.DISPLAY_ORDER, n.CREATED_AT, n.POPUP_ID
```

| 원본 | Oracle |
|---|---|
| `WITH RECURSIVE t AS (...)` | `WITH t (col1, col2) AS (...)` — 컬럼 목록 필수, `RECURSIVE` 키워드 없음 |
| `CASE ... THEN <boolean> ELSE FALSE END` | 1/0 정수 CASE |
| `HAVING BOOL_AND(matched)` | `HAVING MIN(matched) = 1` |
| `usr.*` in CTE | 동일 |
| `<>` / `!=` | 동일 |

"완료 제외" 조건은 **기존 `selectAvailablePopups`에는 넣지 않고** 신규 `selectWpfAvailablePopups`에만 둔다. 기존 WPF-01/`/statuses` 계약(완료를 클라이언트가 제외)이 유지되어야 하기 때문이다.

### 4.5 기타

| 원본 | Oracle |
|---|---|
| `left(replace(gen_random_uuid()::text,'-',''),30)` | `SUBSTR(RAWTOHEX(SYS_GUID()), 1, 30)` |
| `#{x}::numeric`, `CAST(#{x} AS JSONB)` | 캐스트 제거 (`#{x}`), CLOB은 문자열 그대로 |
| `CASE WHEN #{quiz} THEN ...` (boolean 파라미터) | `CASE WHEN #{quizYn} = 'Y' THEN ...` — Java에서 Y/N 문자열로 변환해 전달 (Oracle은 boolean 바인드 불가) |
| `(status.completed_yn = 'Y') AS completed` | `CASE WHEN COMPLETED_YN = 'Y' THEN 1 ELSE 0 END AS COMPLETED` → Java `boolean` |
| `INSERT ... AS alias` | alias 제거 (MERGE로 대체) |
| `CURRENT_TIMESTAMP` | `SYSTIMESTAMP` |
| `ORDER BY ... created_at DESC` | 동일 |
| 예약어 | `LEVEL`, `COMMENT`, `DATE`, `SIZE`는 컬럼명으로 사용하지 않음 (원본에 없음). 별칭 `condition`, `target`, `content`, `template`, `popup`은 예약어 아님이나 가독성을 위해 `c`, `g`, `ct`, `t`, `n`으로 단축 |
