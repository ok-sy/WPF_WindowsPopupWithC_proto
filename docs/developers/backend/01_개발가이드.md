# 백엔드 개발 가이드

> 담당: Spring API, Oracle DDL·Mapper, 관리자 등록/수정, WPF 단건 조회/결과 저장. API 필드·타입·필수값은 [인터페이스 v3.7](../../interfaces/POPUP_INTERFACE_SPEC.md)가 최우선이다.

## 호출 흐름
관리자 웹 등록·수정 → 서버 JSON 검증·정규화 → Oracle 저장 → WPF 로그인/단건 조회(팝업 1건+`deliveryId`) → WPF 결과 1건 전송 → 서버 결과 저장 및 `nextStatus` 응답.

## 책임 경계
- 웹 기본값은 미리보기용. **최종 기본값·검증·정규화는 서버 책임**.
- 인증 사용자 사번과 요청 본문의 임의 `userId`를 혼동하지 않는다. 3111 백엔드 전달용 샘플은 우리 쪽 신규 개발 대상에서 제외.
- 3117 사번 조회·전체 JSON, 3111 직조회/DDL/코드표 등은 실제 업무 계약 수신 범위만 확인.
- 결과 전송은 `deliveryId`, `resultType`, `resultId`, 점수·합격 여부 등 계약에 맞게 검증. 서버가 QUIZ를 재채점하지 않고 WPF가 보낸 `score`·`passed`를 사용한다는 v3.7 보완을 유지한다.
- SURVEY MULTIPLE_CHOICE의 최소·최대 선택 수는 서버에서도 검증한다.
- VIDEO 단독과 VIDEO+QUIZ의 기본 `completionRatio`는 서로 다르다. 상세는 v3.7 계약.
- 동일 결과 중복/충돌·다중 PC·전달 보존·오류 정책은 [ACTIVE_TASKS B](../../policies/ACTIVE_TASKS.md)에서 미확정 범위를 확인한다.

## DB·인계
- Oracle 스키마·이관은 [DB README](../../../db/oracle/README.md)와 실제 DDL 기준.
- mock/샘플 성공은 실제 SSO·개발계 DB·폐쇄망 endpoint 통과가 아니다.
- API 변경 시 계약서, 예제 JSON, 관리자 변환, WPF DTO, 검증 기록의 정합을 함께 확인.

## 배포
- R1은 **로컬 Spring + 원격 개발 Oracle DB** 기준이며 원격 서버 배포 완료를 뜻하지 않는다.
- 보안팀 소프트웨어 매니저 배포는 가능성만 있고 **미확정**. 운영 방식 확정 전 서버 배포 경로를 임의 확정하지 않는다.
