# 프론트엔드 개발 가이드

> 담당: Next.js 관리자 웹(`zero-rule-web`), PopupCommonComponent, CKEditor, 미리보기. 현행 계약은 [API v3.7](../../interfaces/POPUP_INTERFACE_SPEC.md), 정책은 [POLICY](../../policies/POLICY.md)를 따른다. 이 문서는 해당 문서를 복제하지 않는 **개발자용 요약**이다.

## 화면과 데이터 흐름
관리자 등록/수정 → 화면 폼 값 → `toSaveRequestPopup` 등 변환 → 서버 API → Oracle 저장 → WPF 조회/표시. **WEB은 입력·표시·미리보기 fallback을 책임지고, 서버가 최종 검증·정규화·정책 기본값을 책임진다.** 관리자 미리보기 결과가 서버 확정 정책을 대체하지 않는다.

## 공통 컴포넌트
- `PopupCommonComponent`는 DB/저장 API와 분리해 재사용. 독립 입력값과 콜백을 유지한다.
- `pickPopupFields`는 필요한 top-level/content/questions 필드만 선택해 원래 값 그대로 반환한다. `false`, `0`, 빈 문자열, null/누락을 임의 합치지 않는다.
- 등록·수정 API의 최상위 값과 content/문항 추출 범위를 혼동하지 않는다.
- PopupCommonGuide P0~P3 구현 완료 기록과 실제 운영 빌드/화면 검증은 구별한다.

## 에디터·화면
- CKEditor5 Common/Bbs/PopupRich의 중복 로딩·버전 불일치·입력 불능·서식 손실을 확인한다. 구현 완료 기록이 있다고 폐쇄망 실화면 통과를 의미하지 않는다.
- TEXT 서식/들여쓰기·IMAGE 크기·VIDEO 시청 완료·SURVEY 선택 수·QUIZ 문항/채점은 [사용자 옵션 가이드](../../POPUP_USER_OPTION_GUIDE.md)와 [수신 V0.5](../../design/recieve_plan0.5.md)를 대조한다.
- `QUIZ + content.videoEnabled=true`는 동영상+퀴즈. VIDEO 단독과 기본 `completionRatio`가 다르므로 v3.7 계약 참조.
- 미리보기와 WPF 차이는 [기존 정합 검토](../../reviews/POPUP_PREVIEW_WPF_PARITY.md)를 참고.

## 폐쇄망·빌드
- Windows에서 만든 `node_modules`를 Linux 실행 서버로 그대로 복사하면 네이티브 바이너리·플랫폼 패키지 문제가 생길 수 있다. **기존 node_modules 복사 결정은 유지하되 실제 대상 환경에서 검증**한다.
- 현재 폐쇄망 반입은 `node_modules` 복사 방식. 폐기된 pnpm store 오프라인 설치 절차를 활성 기준으로 쓰지 않는다.
- Turbopack·MUI Icon·SVG·CssBaseline·CKEditor·workspace 해석 문제는 과거 [반입 이슈 기록](../../design/20261030_폐쇄망_FRONT_반입_당일_이슈_정리.md)에 증거가 있다.

## 진행 상태
현재 해야 할 일과 검증 회차는 [ACTIVE_TASKS](../../policies/ACTIVE_TASKS.md)의 A-1·R1·R4가 기준. 문서상의 구현 기록만으로 실화면 완료 체크 금지.
