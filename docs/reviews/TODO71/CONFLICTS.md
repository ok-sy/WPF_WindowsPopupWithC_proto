## 71-1~3 조사 결과와 71-4~6 적용 판단

64개 원본 문서와 현재 없는 6개 번호를 포함해 01~70을 목록화했다. 삭제 번호는 08·16·21·40·41·42이며 Git 삭제 커밋과 기존 대조 기록으로 추적한다. [원본 매핑표](INVENTORY.md), [상세 목록](inventory.json), [요건/이력 제목·체크 색인](requirements.csv)을 먼저 작성한 후 아래 기준으로 통합했다.

정책 카테고리는 16개로 유지한다. API 형식(POL-09), 업무 결과(POL-10), 후보 선정(POL-11), 오류·보류(POL-12)를 분리하고 DB(POL-13)와 인계 샘플(POL-14)을 별개로 둔다. 단발성 테스트·배포 메모는 정책 자체가 아닌 근거·실행 안내로 연결한다. 개별 원문 체크 항목의 주/연관 정책은 문서 책임을 상속한 탐색 색인이며 모든 항목을 새 확정 정책으로 승격하지 않는다.

**적용 판단:** 이미 결정 근거와 구현·계약이 일치하는 경계만 정책으로 정리한다. 명시적 보류는 현행 동작 설명과 함께 보류로 남긴다. 원본 이동/삭제는 하지 않는다. 코드 주석은 복잡한 계약 경계에 정책 ID를 연결하고 방어 이유를 보존한다. 기능 코드·기본값·계약·DDL 변경은 수행하지 않는다. 이 검토는 새로운 업무 정책 선택을 대신하지 않는다.

- WPF DTO/표시·창·큐, 웹 변환/미리보기/샘플, Java 조회·결과·서식·일정, Oracle DDL/매퍼의 정책 경계를 정적으로 대조했다. 전 메서드의 모든 행동을 증명한 전수 동적 검증이 아니다.
- 01~70 원문 상태·체크·이력 날짜·삭제 커밋·연관 정책·대표 소스/계약을 기계 판독 목록으로 남겼다. 상태 선언이 없는 초기 설계도 존재를 기록했다.
- 71-4는 확정 정책 요약·근거 연결만 적용했다. C06·C08의 원본 정정은 원문을 이력으로 보존하고 새 색인에서 구분하는 방식으로 처리했다. 문서 전수 정정 완료라고 하지 않는다.

- 71-6은 방어·계약 경계의 주석에 정책 ID를 연결했다. 원문 표식은 이력 근거로 유지하며 동작 이유를 지우지 않았다. 검색 결과는 [comments.csv](comments.csv)에 보존한다.
- 71-7에서 링크·번호 70개·정책 ID·역추적·주석 외 내용 불변을 검사한다. 기존 깨진 링크는 [LINKS.md](LINKS.md)에 분리한다. Markdown 앵커·외부 URL 가용성 및 생성 바이너리 내부 링크는 검사 범위가 아니다.
