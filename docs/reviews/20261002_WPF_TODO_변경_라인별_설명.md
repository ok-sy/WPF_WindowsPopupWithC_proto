## 전후 실행 흐름

기존: Timer가 먼저 다음 정상 주기를 예약 → 목록 조회 → 실패는 넘김. 426은 안내만 표시.

변경: 기존 조회 gate 확인 → Timer 중단 → 결과 큐 Flush → 종료/426 재확인 → 목록 GET(401이면 원 요청 1회 재전송) → 성공은 복구 초기화/서버 주기 적용, 통신 실패는 다음 복구 간격 선택 → finally에서 다음 Timer 하나 예약. 426은 모든 통신 중단 → 안내 닫기 → `App.ExitAgent`로 종료.

- 실제 복구/HTTP/인증/결과 큐 소스 실행 검증 122건 통과. 15회 예약·각 단계 초기화·HTTP 상태 분류·401 재전송·426 파일 보존·추가 요청 차단·진행 중 취소·정기 인증 복구를 포함한다.
- WPF와 `Popup.BehaviorTests`는 cross-target 빌드 경고 0·오류 0. 추가 WPF 렌더링 테스트는 Windows에서 실행해야 한다.
- 현재 동일 네 모서리/동일 두께 구조만 대상으로 한다. 일반 팝업은 12 - 1/2 = 11.5 반경, FULLSCREEN은 0이다. 외곽 스타일을 모서리별로 바꾸면 그때 Clip 계산도 바꿔야 한다.
- WebView2는 별도 HWND이므로 WPF Clip만으로 네이티브 영상 픽셀까지 검증 완료라고 판단하지 않는다. VIDEO 여백/스크롤/전체화면 왕복은 Windows 확인 대기다.
- 임시 SDK 10.0.100으로 검증했다. 저장소의 10.0.400 고정/폐쇄망 NuGet 설정은 유지했다. dist·반입 패키지·Word/PDF는 재생성하지 않았다.
- HTML5 브리지 검증은 Windows 테스트가 만드는 HTML 부재로 ENOENT, 이번 실행은 미완료다. 기존 테스트 통과 기록과 구분한다.
